# 98 · 启动恢复手册

> 配套脚本：`scripts/preboot-check.sh`（重启前体检）、`scripts/rescue.sh`（一键抢救）

## 0. 先判断严重程度

| 现象 | 大概原因 | 走哪一节 |
|---|---|---|
| 卡在 Lenovo/ThinkPad logo | 固件/硬件，与本次改动无关 | 硬件排查 |
| 直接黑屏，无任何输出 | 显卡/内核参数 | §2 抓 GRUB 菜单 |
| 出现 `Welcome to emergency mode` | 某个单元失败或挂载失败 | §3 急救 shell |
| 停在 `A start job is running...` 超时 | 服务等待超时 | §3 |
| 能进 GDM 但登录后黑屏/循环登录 | 桌面/主题/shell | §4 TTY 修复 |
| 桌面能进，但顶栏消失、图标全白 | 主题问题 | §4（`--themes-only`） |

## 1. 风险评估：这次改动为什么不太可能开不了机

| 改动 | 是否在启动关键路径 | 最坏后果 |
|---|---|---|
| `crashkernel=0` | 否 | 内核不预留崩溃内存，**不影响启动** |
| `GRUB_TIMEOUT=1` | 否 | 只是菜单停留 1 秒 |
| 禁用 21 个单元 | **否**（`systemd-logind` / `gdm` / `NetworkManager` / `polkit` / `dbus` 全部未动） | 少了云初始化、崩溃上报、打印机发现等 |
| zram | 否，且是 `swap` 类 | 已在当前会话验证可用，配置经 systemd 解析校验 |
| `swappiness` / BBR | 否 | 运行时参数，即使非法值也只是回退默认 |
| journald 200M | 否 | 日志容量上限 |
| 默认 shell 改 zsh | 否 | 即使 `.zshrc` 有错，登录后只是报错，仍能进 bash |
| WhiteSur 主题 | 否 | 全在 `~/.themes`，最坏是界面难看 |

**真正可能致命的只有两处，且都已在重启前验证过：**

1. `grub.cfg` 语法 —— `grub-script-check` 通过，且内核条目、initramfs 都在；
2. `.zshrc` 语法 —— `zsh -n` 通过，10 秒内可完整加载。

当前体检结果：**22 项通过 / 0 失败**（`./scripts/preboot-check.sh`）。

## 2. 抓 GRUB 菜单

本机 GRUB 超时为 **5 秒**（双系统保留，见 `03-性能优化.md`），菜单里有：

```
Ubuntu
Ubuntu, with Linux 7.0.0-42-generic
Ubuntu, with Linux 7.0.0-42-generic (recovery mode)   ← 出问题首选
Memory test (...)  ×6
Windows Boot Manager (on /dev/nvme0n1p1)
UEFI Firmware Settings
```

### 最简单的入口：菜单自带的 recovery mode

**不需要改任何参数**，直接在菜单里选 `(recovery mode)` 回车即可。它等价于
`systemd.unit=rescue.target`，会进一个最简的 root shell（不需要密码），
然后按 §3 执行 `rescue.sh`。

这是本机最省事的恢复路径——比手工编辑内核参数可靠得多。

若菜单没出现（超时被跳过 / 显示到别的显示器）：

开机时**从看到厂商 logo 起就连续按 `Esc`**（UEFI）或**按住 `Shift`**（部分机器），
菜单出现后按任意键即可停住倒计时。

进入菜单后：

```
e            # 编辑当前条目
```

找到以 `linux` 开头的那一行，做以下之一：

| 目的 | 操作 |
|---|---|
| 看启动日志定位卡点 | 删掉 `quiet splash`（保留 `ro`） |
| 进单用户最简系统 | 行尾追加 `systemd.unit=rescue.target` |
| 完全跳过图形界面 | 行尾追加 `systemd.unit=multi-user.target` |
| 禁用可疑内核参数 | 删掉 `crashkernel=0` 等本次新增参数 |

按 `Ctrl+X` 启动。

> GRUB 命令行：在菜单界面按 `c` 进入，可手敲
> `linux /boot/vmlinuz-7.0.0-42-generic root=UUID=<uuid> ro single` +
> `initrd /boot/initrd.img-7.0.0-42-generic` + `boot`。

## 3. 急救 shell（emergency / rescue 模式）

看到 `Give root password for maintenance` 或直接出现 `#` 提示符时：

```bash
# 1. emergency 模式根分区是只读的，必须先重挂
mount -o remount,rw /

# 2. 进入项目目录（在家目录下，通常已挂载）
cd /home/suonaos/CodeBuddy/work/linux-tune_SuonaOS

# 3. 一键抢救（还原 GRUB、移除新增配置、恢复被禁用的服务）
./scripts/rescue.sh

# 4. 重启
reboot
```

若项目目录不可用（比如 home 未挂载），手工最小操作：

```bash
mount -o remount,rw /
# 恢复原始 GRUB
cp backup/20261103-205748/files/etc/default/grub /etc/default/grub
cp backup/20261103-210132/files/etc/default/grub.d/kdump-tools.cfg /etc/default/grub.d/
update-grub
# 移除本次写入的内核配置
rm -f /etc/sysctl.d/99-linux-tune.conf /etc/systemd/zram-generator.conf
systemctl daemon-reload
# 确认关键服务已启用
systemctl enable NetworkManager
```

## 4. 能开机但桌面异常

按 `Ctrl+Alt+F3` 切到 TTY，登录（用户名 `suonaos`，sudo 免密）：

```bash
cd ~/CodeBuddy/work/linux-tune_SuonaOS

# 主题导致的黑屏/顶栏消失/图标发白
./scripts/rescue.sh --themes-only

# 查看具体错误
journalctl -b -p err --no-pager | tail -30
systemctl --failed
systemctl status gdm

# GDM 没起来
sudo systemctl restart gdm

# gnome-shell 反复崩溃（多半是扩展）
gsettings set org.gnome.shell disable-user-extensions true

# zsh 登录后终端报错，先回 bash
chsh -s /bin/bash      # 或用 sudo chsh -s /bin/bash suonaos
```

> 注意：`Ctrl+Alt+F3` 在 GNOME Wayland 下有效，TTY 是 F3~F6。

## 5. 最坏情况：Live USB 救援

1. 用 Ubuntu ISO 制作启动盘（Ventoy 或 balenaEtcher）；
2. U 盘启动 → 选 **Try Ubuntu**（不安装）；
3. 挂载根分区并 chroot：

```bash
# 确认分区号
lsblk -f
# 假设根分区 nvme0n1p5，EFI 分区 nvme0n1p1
sudo mount /dev/nvme0n1p5 /mnt
sudo mount /dev/nvme0n1p1 /mnt/boot/efi
for i in /dev /dev/pts /proc /sys /run; do sudo mount -B $i /mnt$i; done
sudo chroot /mnt /bin/bash
```

4. chroot 内修复：

```bash
# 恢复 GRUB 原始配置
cp /home/suonaos/CodeBuddy/work/linux-tune_SuonaOS/backup/20261103-205748/files/etc/default/grub /etc/default/grub
cp /home/suonaos/CodeBuddy/work/linux-tune_SuonaOS/backup/20261103-210132/files/etc/default/grub.d/kdump-tools.cfg /etc/default/grub.d/
update-grub

# 清除本次写入
rm -f /etc/sysctl.d/99-linux-tune.conf /etc/systemd/zram-generator.conf
systemctl enable NetworkManager

# 重建 initramfs（怀疑 initramfs 损坏时）
update-initramfs -u -k all

# 重新安装引导（怀疑 EFI 条目损坏时）
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=ubuntu
```

5. 退出并重启：

```bash
exit
sudo umount -R /mnt
sudo reboot
```

## 6. 逐项还原对照表

| 改动 | 还原方法 |
|---|---|
| apt 源 | `sudo cp backup/20261103-205641/files/etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/` |
| GRUB 超时 / crashkernel | `./scripts/rescue.sh` 或手工恢复 `/etc/default/grub` + `grub.d/*.cfg` 后 `update-grub` |
| 被禁用的 21 个服务 | `./scripts/rollback.sh --restore 20261103-205748` |
| zram | `sudo rm /etc/systemd/zram-generator.conf && sudo systemctl daemon-reload && sudo reboot` |
| sysctl | `sudo rm /etc/sysctl.d/99-linux-tune.conf && sudo sysctl --system` |
| journald | `sudo rm /etc/systemd/journald.conf.d/99-linux-tune.conf && sudo systemctl restart systemd-journald` |
| apport | `sudo sed -i 's/^enabled=0/enabled=1/' /etc/default/apport` |
| dotfiles | `rm -f ~/.zshrc ~/.tmux.conf ~/.vimrc ~/.config/starship.toml` |
| 默认 shell | `sudo chsh -s /bin/bash suonaos` |
| 主题 | `./scripts/rescue.sh --themes-only` + `rm -rf ~/.themes ~/.icons ~/.config/gtk-4.0` |
| 输入法 | `rm ~/.config/environment.d/99-input-method.conf` + 注销 |
| 字体 | `rm ~/.config/fontconfig/fonts.conf && fc-cache -f` |

## 7. 已就位的保险措施

| 措施 | 作用 |
|---|---|
| `scripts/preboot-check.sh` | 重启前 22 项体检，GRUB 语法 / initramfs / 关键单元 / shell 语法全覆盖 |
| `scripts/rescue.sh` | 一条命令还原引导与服务，支持 `--dry-run` 预览 |
| `scripts/rollback.sh` | 按批次精确还原文件与目录 |
| `backup/` 4 个批次 | 原始文件副本，路径层级完整 |
| 免密 sudo | TTY / 急救 shell 下无需密码即可修复 |
| `vendor/` 主题源码 | 不依赖网络即可重装主题 |
