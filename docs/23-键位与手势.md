# 23 · 键位与手势

> 脚本：`scripts/24-keys-gestures.sh`
> 声明清单：`dotfiles/desktop/suona-keys.conf.template`
> 需求：`REQ-36`　决策：`ADR-36`

## 1. 设计原则

1. **只新增，不改系统既有快捷键**。冲突检测命中只警告，不覆盖。
2. **主键用 Super**，但命名是 Suona 自己的动作名（终端/文件/计算器/剪贴板/截图），不出现苹果符号或「⌘」字样。
3. **命令不存在就不写绑定**，避免按下去没反应还以为系统坏了。
4. 手势只做**能配的**，配不了就如实写清楚，不装扩展硬凑。

## 2. 键位表

| 动作 | 快捷键 | 命令 | 说明 |
|---|---|---|---|
| 终端 | `Super+Return` | 本机终端（`ptyxis`，找不到再退 `gnome-terminal`/`kgx`） | 安装时解析，不写死 |
| 文件 | `Super+E` | `nautilus --new-window` | 与 Windows 习惯兼容 |
| 计算器 | `Super+C` | `gnome-calculator` | 未安装则自动跳过 |
| 剪贴板历史 | `Super+Shift+V` | `gtk-launch suona-clip`（见 docs/24） | 需先跑 `25-quicklook-clipboard.sh`；`Super+V` 与通知栏开关冲突，已避开 |

**截图不单独绑定**：GNOME 50 已把 `PrintScreen` 交给 Shell 的截图 UI（区域/窗口/全屏三选一），
再绑一个 `gnome-screenshot` 会抢键，而且本机并未安装该包。`Super+Shift+S` 留给用户自行决定。

**刻意不占用 `Super+Space`**：该组合在 GNOME 里是「切换输入源」，被 fcitx5 与系统同时使用，抢过来会引出输入法问题（ISSUE-02 一类）。

## 3. 窗口与工作区（Suona 键位表）

### 3.1 一个容易踩的事实：键位分属三套 schema

| 动作 | 真正管它的 schema | 说明 |
|---|---|---|
| 半屏 / 最大化 / 四分屏 | `org.gnome.shell.extensions.tiling-assistant` | 由 Ubuntu 预装的扩展实现，**不在** `wm.keybindings` |
| 关窗 / 最小化 / 切换窗口 / 工作区 | `org.gnome.desktop.wm.keybindings` | 原生 |
| 切换显示器 | `org.gnome.mutter.keybindings` | 原生 |

只改 `wm.keybindings` 会以为"改了半屏"，实际半屏归扩展管——这就是"统一键位"最容易只做一半的地方。

### 3.2 完整表

| 动作 | 快捷键 | 来源 | 是否本次新增 |
|---|---|---|---|
| 左半屏 / 右半屏 | `Super+←` / `Super+→` | tiling-assistant | 已有，脚本校验 |
| 最大化 | `Super+↑` | tiling-assistant | 已有，脚本校验 |
| 还原 | `Super+↓` | wm.keybindings | 系统默认 |
| 关闭窗口 | `Alt+F4` / **`Super+Q`** | wm.keybindings | **新增** |
| 最小化 | `Ctrl+Alt+KP_0` / **`Super+M`** | wm.keybindings | **新增** |
| 同应用窗口切换 | **`Super` + 反引号键** | wm.keybindings | **新定义** |
| 应用切换 | `Super+Tab` / `Alt+Tab` | wm.keybindings | 系统默认（本来就有 `Super+Tab`） |
| 切工作区 | `Super+Alt+←/→`、`Super+PageUp/PageDown`、`Ctrl+Alt+←/→` | wm.keybindings | 已有，脚本校验 |
| 移动窗口到相邻工作区 | `Super+Shift+PageUp/PageDown` | wm.keybindings | 系统默认 |
| 移动窗口到另一块屏 | `Super+Shift+←/→/↑/↓` | wm.keybindings | **保留**，没动 |
| 概览 | `Super` | Shell | 系统默认 |

### 3.3 为什么是"补而不抢"

- 半屏键归扩展，硬改会和扩展自身逻辑打架（扩展升级还会覆盖回去）。
- `Super+Shift+←/→` 在 GNOME 里是**移窗口到另一块屏**，不是移工作区；
  把它抢过来做工作区，等于让多显示器用户失去唯一入口。
- 所以脚本只做三件事：**补缺失**（`Super+Q`/`Super+M`）、**整体定义一个空键**（`switch-windows`）、
  **校验已有**（半屏、工作区），并把原值逐条记到 `~/.config/linux-tune/wm-keys.tsv` 供回滚。

### 3.4 验收

```bash
./scripts/24-keys-gestures.sh --status     # 看窗口/工作区实际值
./scripts/99-verify.sh                     # 「关闭窗口 Super+Q」「同应用切换」「半屏就位」
```

`99-verify` 只断言"必须有"的三条，其余沿用系统默认——避免把用户的个性化设置判成失败。

## 4. 手势：能做什么、不能做什么

| 能力 | 现状 | 做法 |
|---|---|---|
| 触摸板点按 | 可配 | `tap-to-click=true` |
| 自然滚动 | 可配 | `natural-scroll=true`（触摸板 + 鼠标） |
| 打字防误触 | 可配 | `disable-while-typing=true` |
| 热角（左上角进概览） | 可配 | `enable-hot-corners=true`（键不存在则跳过） |
| 三指/四指滑动方向 | **不可配** | Shell 内部实现，无 gsettings 开关 |
| 自定义手势（画圈、双击标题栏…） | **需扩展** | 与 ADR-24「少用扩展」冲突，不引入 |

结论：手势层做到「行为参数统一」，不做「自定义手势引擎」。这是明确的取舍，不是遗漏。

## 5. 添加一条自己的键位

编辑 `dotfiles/desktop/suona-keys.conf.template`，加一行：

```
editor | 编辑器 | gnome-text-editor | <Super>n
```

然后重跑：

```bash
./scripts/24-keys-gestures.sh --install
```

- `id` 只用小写字母/数字/连字符（会成为 dconf 路径）
- 命令的第一个词必须存在，否则该条自动跳过
- 重跑是幂等的：已在数组里的路径不会重复追加

## 6. 冲突排查

脚本会扫这四个 schema：

```
org.gnome.desktop.wm.keybindings
org.gnome.shell.keybindings
org.gnome.settings-daemon.plugins.media-keys
org.gnome.mutter.keybindings
```

命中会在输出里打印 `⚠ <动作>：<组合> 可能与既有绑定冲突 → <命中行>`。
此时**不要**强行保留，换一个组合或先解绑原动作。

手工核查：

```bash
gsettings list-recursively org.gnome.desktop.wm.keybindings | grep -F "'<Super>e'"
./scripts/24-keys-gestures.sh --status
```

## 7. 为什么数组键不能单独 set

`custom-keybindings` 是一个字符串数组。直接

```bash
gsettings set ... custom-keybindings "['/org/.../suona-terminal/']"
```

会把别的工具（输入法、截图工具、扩展）注册的条目**整体覆盖**。
所以脚本的做法是：`dconf dump` 备份 → 读出数组 → 只追加自己的路径 → 整体写回；
`--restore` 也只摘掉 `suona-*` 前缀的条目，不动别人的。

## 8. 回滚

```bash
./scripts/24-keys-gestures.sh --restore
```

- 启动器键位：只移除 `custom-keybindings` 里自己的条目，不动其它工具；
- 窗口/工作区键位：按 `~/.config/linux-tune/wm-keys.tsv` 记录的原值逐条还原（倒序回放），然后删除记录文件。

系统快捷键与其它工具注册的绑定保持原样。
若要连热角/触摸板参数一起回到默认，需手工：

```bash
gsettings reset org.gnome.desktop.interface enable-hot-corners
gsettings reset org.gnome.desktop.peripherals.touchpad tap-to-click
```
