# 15 · 声音主题（Suona）

> 脚本：`scripts/11-sound-theme.sh`　决策：`ADR-27`　需求：`REQ-26`

一套本地合成的 GNOME 提示音主题，遵循 freedesktop sound-theme 规范。
目录名 `Suona`，与项目同名；音色取「木腔 / 瓷击 / 哨片」三族，
呼应唢呐的木质管身与簧片，但**刻意压短、压轻**，不做旋律化提示音。

## 1. 为什么是本地合成

| 方案 | 问题 |
|---|---|
| 下载现成音效包（freesound / Kenney） | 授权多为 CC0/CC-BY，可用但**引入素材依赖**：换机、重装、离线都要再取；BY 类还要维护 `CREDITS.txt` |
| 采样真实唢呐 | 音色本身高亢刺耳，做 UI 提示音会疲劳；且需要授权链 |
| **ffmpeg `aevalsrc` 合成** | 无第三方素材、无授权负担、可复现、改参数即改音色，产物仅 252 KB |

选定第三条：整套音效由一段 shell 里的数学表达式生成，
`git` 里只有脚本，没有二进制，改音高/衰减/音色只需改事件表一行。

用到的开源件：**ffmpeg**（LGPL/GPL，系统自带）、**libcanberra**（LGPL，GNOME 播放层）、
**freedesktop sound-theme 规范**（事件命名与目录结构）。三者都是系统既有组件，**零新增依赖**。

## 2. 规范与目录

libcanberra 的查找顺序：`~/.local/share/sounds/<theme>/` → `/usr/share/sounds/<theme>/`，
找不到具体事件时回落到 `freedesktop`。

```
~/.local/share/sounds/Suona/
├── index.theme
└── stereo/
    ├── bell.oga
    ├── message.oga
    └── ... 共 34 个
```

`index.theme`：

```ini
[Sound Theme]
Name=Suona
Comment=Suona 木腔提示音（ffmpeg 合成，无第三方采样）
Directories=stereo

[stereo]
OutputProfile=stereo
```

## 3. 三个音色族

| 族 | 波形构成 | 衰减 | 时长 | 用途 |
|---|---|---|---|---|
| `wood` 木腔 | 基频 + 2.72× + 5.27× 谐波（非整数比，木质感） | `exp(-15t)` | 0.42s | 消息、完成、设备插拔 |
| `porcelain` 瓷击 | 基频 + 1.67× + 2.57×，衰减极快 | `exp(-26t)` | 0.30s | 信息提示、窗口注意、垃圾桶 |
| `reed` 哨片 | 单音 + 5.5Hz 颤音（`0.9·sin(2π·5.5t)` 相位调制）+ 70Hz 起振 | `exp(-4.5t)` | 0.80s | 响铃、登录/登出、来电 |
| `lowwood` 低木 | 基频 + 1.9× + 3.1×，低频慢衰减 | `exp(-8t)` | 0.65s | 错误、挂断、休眠失败 |

「唢呐感」只保留在 `reed` 族的颤音与起振上，且**不用于高频事件**——
日常最多的消息/音量提示走木腔与瓷击，避免长期使用产生听觉疲劳。

## 5. 音量匹配：系统音效不能压过应用

### 5.1 结构性问题

GNOME 50 的 `org.gnome.desktop.sound` 只有 4 个键：

```
allow-volume-above-100-percent  event-sounds  input-feedback-sounds  theme-name
```

**没有「系统音效音量」**。而 libcanberra 播放提示音时创建的流是
`media.role = "event"`、`module-stream-restore.id = "sink-input-by-media-role:event"`，
与应用音频**共享同一个 sink 音量**。于是：

| 对象 | 典型值 |
|---|---|
| 应用内容（音乐/会议） | 响度约 −14 LUFS，峰值 −1 dBFS |
| 第一版提示音 | 峰值 −3.5 dBFS |

峰值只差 2.5 dB ⇒ 提示音几乎和音乐一样响，短促音反而更刺耳。
这就是「系统声音和应用音量不匹配」的实际表现。

### 5.2 试过但无效的方案

给 WirePlumber 写 `stream.rules` 匹配 `media.role=event` 并设 `target.volume=0.5`：

```conf
stream.rules = [
  { matches = [ { media.role = "event" } ]
    actions = { update-props = { target.volume = 0.5 } } }
]
```

写好 `systemctl --user restart wireplumber` 后服务 `active`、日志无报错，
但 `pactl list sink-inputs` 显示 event 流仍为 `65536 / 100% / 0.00 dB`，
`~/.local/state/wireplumber/stream-properties` 里也没有 event 记录。
说明规则被加载，但 `update-props.target.volume` 对 client stream 不生效
（pulse 层默认音量优先）。该配置已删除，没有留在系统里。

### 5.3 采用方案：生成端固定衰减

音效文件本来由脚本生成，整体降一档最可靠：

- 常量 `SYS_DECAY_DB`，默认 **−6.5 dB**
- 叠加在逐文件归一化之后：`实际目标 = 基准峰值 + SYS_DECAY_DB`
- 存 `~/.config/linux-tune/sound.conf`，重跑脚本不会丢
- 临时调整：`./scripts/11-sound-theme.sh --decay -3`

实际输出：

| 事件类 | 基准 | 实际峰值 |
|---|---|---|
| 默认（消息 / 完成 / 插拔…） | −3.5 | **−10.0 dBFS** |
| `dialog-error` / `suspend-error` | −2.5 | −9.0 |
| `camera-shutter` | −4 | −10.5 |
| `screen-capture` | −7 | −13.5 |
| `audio-volume-change`（刻度音） | −7 | −13.5 |

与应用内容峰值（−1 dBFS）拉开约 9 dB，既能听清又不抢戏。

### 5.4 归一化本身的做法

不按波形系数拍脑袋，而是**逐文件测量**：

1. 渲染成 PCM WAV（`pcm_s16le`，不做有损）
2. `volumedetect` 读 `max_volume`
3. 计算差值，`volume=<dB>` 后一次性编码 Ogg Vorbis（q5，避免二次压缩）
4. 提升上限 +18 dB，避免把合成底噪一起抬起来

首版按系数估算时，reed 族实测只有 −19 dB、快门 −0.5 dB；改为测量后
34 个文件全部落在目标 ±0.3 dB 内。

## 6. 使用

```bash
./scripts/11-sound-theme.sh              # 生成 + 安装 + 切换（幂等，可反复跑）
./scripts/11-sound-theme.sh --dry-run    # 只看将生成什么
./scripts/11-sound-theme.sh --list       # 事件表 + 文件 + 当前主题
./scripts/11-sound-theme.sh --preview    # 逐个试听（paplay）
./scripts/11-sound-theme.sh --restore    # 恢复安装前的主题
```

安装动作只有三件：写 `~/.local/share/sounds/Suona/`、
`gsettings set org.gnome.desktop.sound theme-name Suona`、打开 `event-sounds`。

原主题值写入 `backup/<RUN_ID>/sound-theme.txt` 并登记 `logs/changes.tsv`。
**只在首次从非 Suona 切过来时备份**：重复执行不会覆盖真实原值，
否则 `--restore` 会退化成「回滚到 Suona 自己」。`--restore` 也会跳过值为 `Suona`
的批次，取更早的非 Suona 记录。

## 7. 验证证据

```bash
# 1. 主题被识别且真的读了我们的文件（不是回落 freedesktop）
strace -f -e trace=openat canberra-gtk-play -i bell 2>&1 | grep sounds/
# → openat(..., "/home/suonaos/.local/share/sounds/Suona/stereo/bell.oga", O_RDONLY) = 16

# 2. 批量峰值
for f in ~/.local/share/sounds/Suona/stereo/*.oga; do
  ffmpeg -hide_banner -i "$f" -af volumedetect -f null /dev/null 2>&1 | grep max_volume
done

# 3. 体检（99-verify 美化段后新增「声音主题」5 项）
./scripts/99-verify.sh
```

`99-verify.sh` 按 ADR-21 做**状态感知**：当前主题为 `Suona` 时断言 5 项
（主题名、`index.theme`、事件音 ≥20、`event-sounds=true`、`bell.oga` 峰值 ≤ −8 dBFS）；
非 `Suona` 时只断言「主题名非空且不等于 Suona」，回退后不会假失败。

## 8. 已知限制

| 现象 | 原因 | 处理 |
|---|---|---|
| 改了音色但听到的还是旧的 | libcanberra 每次播放都重读文件，但**已缓存的文件句柄**不会变 | 重跑脚本即可；无需注销 |
| 部分应用提示音没变 | 应用自带音效（如浏览器、Electron 应用）不走 libcanberra | 属应用层，不在本主题范围 |
| Shell 自身响铃 | GNOME Shell 用 `bell` 事件，已覆盖 | — |
| 某些事件听不到 | GNOME 并未在所有场景触发（如 `trash-empty` 只在文件管理器清空回收站时） | 属事件触发条件，非主题问题 |
| 总音量很低时觉得提示音听不见 | 峰值已压到 −10 dBFS，再经 sink 衰减 | 属正常比例关系；需要更响用 `--decay -3` |
| 无 `paplay` | `--preview` 依赖 `pulseaudio-utils` | `apt install pulseaudio-utils`；系统已有 `pw-play` 可替代 |

## 9. 回滚

```bash
./scripts/11-sound-theme.sh --restore          # 恢复安装前的 theme-name
rm -rf ~/.local/share/sounds/Suona             # 需要时删除主题目录
gsettings reset org.gnome.desktop.sound theme-name   # 或直接回系统默认
```
