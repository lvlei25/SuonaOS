# 03 · 性能优化

> 脚本：`scripts/03-perf-tune.sh`
> 用法：`./scripts/03-perf-tune.sh [--dry-run]`

优化前基线：开机 **26.408s**，运行中服务 36 个，`swappiness=60`，无 zram，`crashkernel` 预留 320M。

---

## 1. 启动关键路径

### NetworkManager-wait-online

```
6.633s NetworkManager-wait-online.service
```

它让 `network-online.target` 在「网络真正可用」后才算完成，服务端场景有用，
桌面机纯属拖慢开机（占了 userspace 11.1s 的 60%）。

```bash
sudo systemctl disable --now NetworkManager-wait-online.service
```

### GRUB 超时

`/etc/default/grub` 里 `GRUB_TIMEOUT` 默认 5s，单系统可改为 1s：

```bash
sudo sed -i 's/^GRUB_TIMEOUT=.*/GRUB_TIMEOUT=1/' /etc/default/grub
sudo update-grub
```

### ⚠️ 本机例外：Windows 双系统，保留 5s

体检时发现这台机器是双系统：

```
nvme0n1p1   200M vfat   /boot/efi   （EFI 里同时有 Microsoft 与 ubuntu）
nvme0n1p3 187.3G ntfs              Windows 11
nvme0n1p5 288.5G ext4              Ubuntu 根分区
```

GRUB 菜单里因此有 6 个以上条目：Ubuntu、Ubuntu recovery mode、memtest ×6、
**Windows Boot Manager**、UEFI Firmware Settings。

超时改 1s 的代价是几乎选不到 Windows，也抓不到 recovery mode。
**本机最终保留 5s**，牺牲约 4 秒换可用性——这个取舍对双系统是划算的。

> 顺带一个事实：`grub.cfg` 里出现两个 `set timeout=`，`30` 那个在
> `if [ "${recordfail}" = 1 ]` 分支里（上次启动失败时自动延长），正常分支是 5。
> 用 `grep -n 'set timeout=' /boot/grub/grub.cfg` 能看到全部，别被第一个吓到。

## 3. zram 压缩内存

用 `systemd-zram-generator`（比 `zram-tools` 更贴近 systemd 原生方式）：

```bash
sudo apt install -y systemd-zram-generator
```

`/etc/systemd/zram-generator.conf`：

```ini
[zram0]
zram-size = min(ram / 2, 8192)
compression-algorithm = zstd
swap-priority = 100
fs-type = swap
```

参数含义：

| 键 | 值 | 说明 |
|---|---|---|
| `zram-size` | `min(ram/2, 8192)` | 13G 内存 → 6.9G 压缩交换区，上限 8G 防止过度占用内存 |
| `compression-algorithm` | `zstd` | 比 lz4 压缩率高，比 lzo 快，笔记本权衡最优 |
| `swap-priority` | `100` | 高于 `/swap.img` 的 `-1`，内核优先用 zram |

实际效果：

```
NAME       TYPE      SIZE USED PRIO
/swap.img  file        4G   4K   -1
/dev/zram0 partition 6.9G   0B  100
```

总交换 10.9G，且压缩比通常 2.5~3:1，等效 17~20G 可用交换，
代价是几乎不写 SSD。

**为什么值得开：** 13G 内存 + Chrome + IDE 容易触发 swap。
磁盘 swap 一旦发生就是 100ms 级卡顿；zram 是内存内解压，微秒级。

## 4. sysctl 参数

`/etc/sysctl.d/99-linux-tune.conf`：

```ini
vm.swappiness = 10
vm.page-cluster = 0
vm.vfs_cache_pressure = 50
vm.dirty_ratio = 15
vm.dirty_background_ratio = 5
vm.dirty_expire_centisecs = 3000
vm.dirty_writeback_centisecs = 1500
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
net.ipv4.tcp_fastopen = 3
net.core.somaxconn = 4096
fs.inotify.max_user_watches = 524288
fs.inotify.max_user_instances = 1024
fs.file-max = 2097152
```

| 参数 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `swappiness` | 60 | 10 | 有 zram 后应谨慎换出匿名页；60 会让内核过早把热数据换到 zram，徒增 CPU |
| `page-cluster` | 3 | 0 | zram 下预读无意义，还会放大随机访问开销 |
| `vfs_cache_pressure` | 100 | 50 | 更倾向保留 inode/dentry 缓存，文件遍历更快 |
| `dirty_ratio` | 20 | 15 | 降低单次回写峰值，避免突发 IO 卡顿 |
| `dirty_writeback_centisecs` | 500 | 1500 | 5s → 15s 批量回写，SSD 写放大更小 |
| `tcp_congestion_control` | cubic | bbr | 高延迟链路吞吐更好 |
| `inotify.max_user_watches` | 65536* | 524288 | 大型前端项目 / IDE 文件监视会撞上限 |

> `dirty_writeback_centisecs` 调大意味着断电时可能丢最多 15s 未落盘数据。
> 如果这台机器经常直接断电，改回 500。

## 5. crashkernel 与 GRUB

原参数：`crashkernel=2G-4G:320M` —— 在 2~4G 内存区间预留 320M，
本机 13G 走的是 `4G-32G:512M` 分支，实际预留 **512M**。

改为 `crashkernel=0`：

```bash
sudo sed -i -E 's/crashkernel=[^ "]*//g' /etc/default/grub
sudo sed -i -E 's/^(GRUB_CMDLINE_LINUX_DEFAULT=")(.*)"/\1\2 crashkernel=0"/' /etc/default/grub
```

### ⚠️ 关键陷阱：`/etc/default/grub.d/*.cfg`

第一次改完 `grub.cfg` 里出现了**两个** crashkernel：

```
quiet splash crashkernel=0 crashkernel=2G-4G:320M,4G-32G:512M,...
```

原因：`kdump-tools` 包会安装 `/etc/default/grub.d/kdump-tools.cfg`：

```bash
GRUB_CMDLINE_LINUX_DEFAULT="$GRUB_CMDLINE_LINUX_DEFAULT crashkernel=2G-4G:320M,..."
```

`/etc/default/grub` 编辑完后，`/etc/default/grub.d/*.cfg` 会被 **重新 source**，
在内核命令行末尾追加该参数。内核取**最后出现**的值，于是 `crashkernel=0` 被覆盖。

正确做法是先清理片段文件：

```bash
sudo tee /etc/default/grub.d/kdump-tools.cfg >/dev/null <<'EOF'
# crashkernel 预留已移除（kdump-tools 已禁用）
GRUB_CMDLINE_LINUX_DEFAULT="$GRUB_CMDLINE_LINUX_DEFAULT"
EOF
sudo update-grub
```

验证：

```bash
sudo grep -m1 -o 'quiet splash.*' /boot/grub/grub.cfg
# 期望: quiet splash crashkernel=0
```

## 6. journald

`/etc/systemd/journald.conf.d/99-linux-tune.conf`：

```ini
[Journal]
SystemMaxUse=200M
SystemMaxFileSize=50M
RuntimeMaxUse=50M
Compress=yes
```

默认上限是磁盘的 10%（本机约 28G），长期运行会吃掉可观空间。

## 8. 回滚

```bash
./scripts/rollback.sh --list
./scripts/rollback.sh --restore <RUN_ID> --dry-run   # 先预览
./scripts/rollback.sh --restore <RUN_ID>
```

回滚脚本会还原 `/etc/default/grub`、`grub.d/*.cfg`、`sysctl.d`、`journald.conf.d`、`apport`，
并 `enable` 所有被禁用的单元；GRUB/crashkernel 需重启生效。
