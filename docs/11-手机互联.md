# 11 · 手机互联（红米 HyperOS · 手机端零安装）

> 关联：REQ-20 / REQ-21 / TASK-24,28~32 / ISSUE-16,18,19 / ADR-14,15
> 环境：Ubuntu 26.04.1 + GNOME 50.1 Wayland；手机为红米（HyperOS / Android）
> **约束：手机端不安装任何第三方 App。**

## 1. 为什么不用 KDE Connect / GSConnect / LocalSend

这三者都要求在手机端安装常驻应用才能配对。用户明确拒绝，故全部弃用（ADR-15）。
桌面端已安装的 `gnome-shell-extension-gsconnect` 成为冗余，**不启用**即可，
可选卸载（TASK-32）。

## 2. 方案：ADB-only

ADB 是 Android 系统自带的调试通道，通过「开发者选项」开启即可，**不需要装 App**。
`scrcpy` 只是把 server 临时 push 到 `/data/local/tmp` 运行，退出后不残留为应用。

| 能力 | 手段 | 手机端要求 |
|---|---|---|
| 投屏 + 键鼠反向控制 | `scrcpy` | USB 调试 |
| 文件双向传输 | `adb push` / `adb pull`；或拖文件到 scrcpy 窗口 | USB 调试 |
| 剪贴板双向 | scrcpy 窗口内 `Ctrl+C` 取手机 / `Ctrl+V` 推送中文 | USB 调试 |
| 免 USB 线 | HyperOS「无线调试」+ `adb pair` / `adb connect` | 无线调试 |
| 通知同步 / 电量 / 寻响 / 电话 | **不提供** | 需常驻 App，已放弃 |

桌面工具已就位（2026-11-05 核验）：`adb 1.0.41 / 34.0.5-debian`、`scrcpy 3.3.4`，
**零新增安装**。`gvfs-mtp` 未装，不影响本方案（走 adb 而非 MTP）。

## 3. 手机端一次性设置（红米 / HyperOS）

1. **设置 → 我的设备 → 全部参数 → 连点「OS 版本」7 次**，输入锁屏密码，开启开发者选项。
2. **设置 → 更多设置 → 开发者选项**：
   - 打开「USB 调试」；
   - 若出现「USB 调试（安全设置）」**不要开启**（scrcpy 不需要，且 HyperOS 要求登录小米账号 + SIM 卡）。
3. USB 线连接电脑，手机通知栏把 USB 模式选为「传输文件(MTP)」或「仅充电」均可；
   弹出「允许 USB 调试吗？」时**勾选一律允许**并点确定。
4. **保持手机解锁**：HyperOS 锁屏后可能撤销 adb 授权。

> 安全提示：`adbd` 在 USB 调试开启期间可被本机调试。用完请在开发者选项里关闭
> 「USB 调试」，或拔线。不要在公共电脑/充电站上开启。

## 4. 验收与日常使用

```bash
# 位置：~　sudo：否　只读
adb devices -l
```

期望出现一行且状态为 `device`：

```
List of devices attached
xxxxxxxx        device usb:... product:... model:Redmi_... 
```

| 状态 | 含义 | 处理 |
|---|---|---|
| `unauthorized` | 未点「允许 USB 调试」 | 解锁手机，重新插拔，点允许 |
| `no permissions` | udev 规则缺失 | 见第 7 节 |
| 无输出 | 线材不支持数据 / 未开调试 / 模式不对 | 换原装线，检查开关 |

### 投屏与控制

```bash
scrcpy                       # 默认启动
scrcpy --max-size 1080 --max-fps 60 --stay-awake   # 常用参数
scrcpy --turn-screen-off     # 熄屏投屏（省电，需设备支持）
```

scrcpy 窗口内快捷键：

| 键 | 作用 |
|---|---|
| `Ctrl+C` | 把手机剪贴板取到电脑 |
| `Ctrl+V` | 把电脑剪贴板（含中文）推到手机 |
| `Ctrl+Shift+V` | 直接把电脑剪贴板内容注入为输入 |
| `Ctrl+f` | 全屏 |
| `Ctrl+o` | 关闭手机屏幕 |
| 拖入文件 | push 到 `/sdcard/Download`（默认） |

### scrcpy 没有工具栏按钮：用快捷键操作手机

scrcpy 窗口是**纯画面**，没有「返回 / 主页 / 多任务」按钮。
本机红米 `navigation_mode=2`（AOSP：`0` 三键 / `1` 两键 / `2` 全手势），
手机画面里同样没有三键导航栏 —— 这不是故障。

`MOD` = 修饰键，默认是**左 Alt 或左 Super**：

| 快捷键 | 作用 |
|---|---|
| `MOD+b` / 鼠标右键 | 返回 BACK |
| `MOD+h` / 鼠标中键 | 主页 HOME |
| `MOD+s` | 多任务 APP_SWITCH |
| `MOD+n` | 下拉通知栏 |
| `MOD+o` | 熄屏（手机继续运行） |
| `MOD+p` | 电源键 |
| `MOD+f` | 全屏 |
| `MOD+c` / `MOD+v` | 取手机剪贴板 / 推送电脑剪贴板 |
| `MOD+↑` / `MOD+↓` | 音量 |

**Super 键会被 GNOME 抢走**（打开 Activities），建议改用左 Alt，
或在启动时把修饰键固定为左 Ctrl：

```bash
scrcpy -s 192.168.31.196:39959 --shortcut-mod=lctrl --max-size 1080 --max-fps 60 --stay-awake
```

手势也可以直接用鼠标拖：从屏幕左/右边缘向内拖 = 返回，
从底部向上拖 = 主页，底部上拖后停住 = 多任务。

若确实想让画面出现三键按钮（改手机设置，不装 App）：
设置 → 桌面 / 更多设置 → 系统导航方式 → 「经典三键导航」。
投屏画面会立刻出现返回/主页/多任务按钮，适合演示给别人看。

## 5. 免 USB 线：HyperOS 无线调试（REQ-21，已连通）

Android 11+ / HyperOS 自带，无需装 App。

**本机实测成功记录（2026-11-05）**：

```
192.168.31.196:39959   device product:manet model:23117RK66C device:manet transport_id:2
```

设备：红米 `23117RK66C`（代号 manet），Android 16，安全补丁 2026-09-01，
物理分辨率 1440x3200（系统覆写为 1080x2400）。

### 5.1 端口用途以界面文字为准，不要靠数字猜

HyperOS「无线调试」页面可能出现两类端口：

| 来源 | 用途 | 命令 |
|---|---|---|
| 「使用配对码配对设备」弹窗 | TLS 配对（首次） | `adb pair <IP>:<配对端口>` |
| 「无线调试」主页面「IP 地址和端口」 | 普通 adb 连接 | `adb connect <IP>:<连接端口>` |

**重要更正**：本机 `39959` 曾被误判为配对端口，实际就是**连接端口**
（`adb connect` 后状态为 `device`）。随机高端口既可能是配对端口也可能是连接端口，
**必须看它出现在哪个界面**，不能凭端口号形态推断（ISSUE-21）。

首次连接失败时的正确排查顺序：

1. 手机**保持解锁**、无线调试开关确认为开（HyperOS 锁屏 / Wi-Fi 切换会自动关闭）；
2. 若从未配对过，先点「使用配对码配对设备」执行一次 `adb pair`；
3. 用主页面的 `IP:端口` 执行 `adb connect`；
4. 仍失败则 `adb kill-server && adb start-server` 后重试，
   并用 `ADB_TRACE=all adb connect ... 2>&1 | tail -30` 看握手阶段。

**替代方案**：插 USB 线执行 `adb tcpip 5555`，拔线后
`adb connect <手机IP>:5555`，端口固定、不用配对码；代价是手机重启后要重跑一次。

诊断要点：`ping` 不通不代表故障（Android 通常不回 ICMP）；
用 `timeout 2 bash -c "echo >/dev/tcp/<IP>/<端口>"` 判断端口是否真的可达。
本次实测：39959 TCP 可连、5555 不通、ping 100% 丢包，但 adb 连接成功。

### 5.2 一键连接（推荐，REQ-22 / ADR-16）

日常不需要手输 `adb connect` 与一长串 scrcpy 参数，用项目脚本：

```bash
cd ~/CodeBuddy/work/linux-tune_SuonaOS

./scripts/mobile-connect.sh              # 自动连接 + 投屏（复用上次成功地址）
./scripts/mobile-connect.sh 39959        # 端口变了：指定一次，之后自动记住
./scripts/mobile-connect.sh --status     # 只看状态
./scripts/mobile-connect.sh --stop       # 断开
./scripts/mobile-connect.sh --tcpip      # 可选：固定为 5555，长期免输端口
```

脚本做四件事：取已连接设备 → 无则复用 `~/.config/linux-tune/mobile.conf` 里记住的地址
→ 固化投屏参数（含 `--shortcut-mod=lctrl`）→ 避免重复启动 scrcpy。
配置与日志分别在 `~/.config/linux-tune/mobile.conf`、`logs/mobile-connect.log`。

**端口变化是唯一需要人工的场景**：手机重启 / Wi-Fi 切换 / 开发者选项关闭后，
到「无线调试」主页面看一眼新端口，执行 `mobile-connect.sh <新端口>` 一次即可。

**为什么不做全自动**：实测 `adb mdns services` 返回空、
`avahi-browse -rt _adb-tls-connect._tcp` 也无输出，HyperOS 不广播 ADB 服务，
mDNS 自动发现不可用；定时轮询重连又属常驻侵入。故采用「记忆 + 单次覆盖」。

#### 5.2.1 `--status` 自诊断

连不上时先跑 `--status`，它会沿「IP 可达 → 端口开放 → adb 握手」三段依次判定：

```
$ ./scripts/mobile-connect.sh --status
List of devices attached

scrcpy: 未运行
已保存地址: 192.168.31.196:39959

诊断:
  手机 IP : 192.168.31.196
  网络可达: 是（ARP f6:a5:02:1e:ca:7c）
  端口 39959: 关闭
  结论: 无线调试已关闭，或端口已变（HyperOS 每次重开都换端口）
  建议: 手机打开「无线调试」后执行 mobile-connect.sh <新端口>
```

四种结论与处置：

| 现象 | 结论 | 处置 |
|---|---|---|
| `网络可达: 否（INCOMPLETE）` | 手机离线 / 换了网络 / IP 变了 | 核对手机无线调试页上的 IP |
| `端口 xxx: 关闭` | 无线调试关闭，或端口变了 | 手机上重开无线调试，用新端口连一次 |
| `端口 xxx: 开放` 但无设备 | 端口通、未完成授权 | 看手机「允许调试」弹窗，或 `--stop` 后重连 |
| 有 `device` 行 | 正常 | 直接 `mobile-connect.sh` 投屏 |

**实现要点**：HyperOS 默认丢弃 ICMP，只看 `ping` 会把在线手机误判为离线；
所以先用 `ping` 触发 ARP 解析，再读 `ip neigh` 的邻居状态（`REACHABLE`/`STALE`）。
端口探测用 bash 的 `/dev/tcp`，2 秒超时，不依赖 `nc`。

#### 5.2.2 锁屏导致画面中断

**现象**：投屏看着看着画面突然变黑，但 scrcpy 窗口在、adb 也还连着。

**根因**不是连接断开，是手机息屏：

```
mWakefulness=Dozing
screen_off_timeout      = 15000    ← 15 秒没操作就关屏
stay_on_while_plugged_in = 7       ← 只对「插电」生效
```

无线投屏时手机通常没插电，所以 `stay_on_while_plugged_in` 完全不生效，
`--stay-awake`（等价 `svc power stayon`）也一样无效——Android 只在充电时才保持唤醒。

**修复**：`mobile-connect.sh` 在启动 scrcpy 前把 `screen_off_timeout` 临时拉满，
退出时（含 Ctrl+C、关窗口、`--stop`）自动恢复：

```
投屏期间已关闭自动息屏（原值 15000ms，退出后恢复）
...
已恢复自动息屏（15000ms）
```

原值存在 `~/.local/state/linux-tune/screen-timeout.bak`，
即使脚本异常终止，`mobile-connect.sh --stop` 也会兜底恢复。

> 注意：**手动按电源键锁屏仍会黑屏**，这是 Android 的正常行为（屏幕关了就没有画面）。
> 本修复只解决「放着不动自动息屏」导致的中断。

### 5.3 文件互传

**电脑 → 手机：拖进 scrcpy 窗口（需 `--x11`）**

scrcpy 3.3.4 支持拖放，但**只在 X11/XWayland 后端可用**：
它依赖 SDL2 的 `SDL_DROPFILE` 事件，而 SDL2 的 **Wayland 后端没有实现该事件**，
所以原生 Wayland 下拖文件进窗口毫无反应。

```bash
./scripts/mobile-connect.sh --x11     # 走 XWayland，拖放可用
./scripts/mobile-connect.sh           # 原生 Wayland，更清晰但没有拖放
```

| 拖入内容 | 行为 |
|---|---|
| 普通文件 | 推到 `/sdcard/Download/` |
| APK | 自动静默安装 |
| 目录 | 递归推送 |

想改落点可加 `--push-target=/sdcard/DCIM/`。

> **为什么要额外做 DPI 换算**：SDL2 的 X11 后端按**物理像素**建窗，
> 而脚本里的 414×920 是**逻辑像素**。本机 200% 缩放（`Xft.dpi=192`）下
> 若不换算，窗口只有屏幕 12% 宽，看起来"特别小"。
> `--x11` 模式会读 `xrdb` 的 `Xft.dpi` 自动乘以缩放因子（此处 ×2 → 756×1680）。

**手机 → 电脑：scrcpy 不支持拖出**，用下面两种之一。

| 方式 | 适用 | 命令 |
|---|---|---|
| USB + MTP | 想拖拽 | 插线后手机选「文件传输」，Nautilus 侧栏直接拖 |
| `18-mobile-file.sh` | 无线、批量、脚本化 | 见下 |

```bash
# 电脑 → 手机（默认 /sdcard/Download/）
./scripts/18-mobile-file.sh --push ~/报告.pdf ~/照片/
./scripts/18-mobile-file.sh --to /sdcard/DCIM/Camera --push ./IMG_001.jpg

# 手机 → 电脑（默认 ~/Downloads/）
./scripts/18-mobile-file.sh --pull /sdcard/DCIM/Camera/IMG_20261111.jpg
./scripts/18-mobile-file.sh --pull /sdcard/Download/某个目录

# 看手机目录
./scripts/18-mobile-file.sh --ls /sdcard/Download

# 状态
./scripts/18-mobile-file.sh --status
```

脚本复用 `mobile.conf` 里记住的地址：无设备时会自动尝试重连一次，
失败则提示先跑 `mobile-connect.sh --status` 诊断（多数是无线调试被关）。

MTP 后端本机已装齐（`gvfs-backends 1.60`、`libmtp 1.1.22`、`gvfsd-mtp`），
插 USB 后无需额外安装。

**把文件「交给」手机上的 App**

scrcpy 的拖放只是 `adb push` 到 `/sdcard/Download/`，**不会交给任何 App**；
Android 也没有通用的「拖放接收」接口（`ACTION_DRAG_*` 只在 App 内部有效，
桌面无法跨进程投放）。等效做法是用 `SEND` intent：

```bash
./scripts/19-mobile-share.sh --share ~/照片.jpg          # 推到手机并交给 App
./scripts/19-mobile-share.sh --share ~/报告.pdf --app wechat
./scripts/19-mobile-share.sh --open /sdcard/Download/a.jpg   # 用默认 App 打开
```

行为：

1. `adb push` 到 `/sdcard/Download/`，并广播 `MEDIA_SCANNER_SCAN_FILE` 让相册索引
2. 构造 `content://com.android.externalstorage.documents/...` URI
   （不能用 `file://`，Android 7+ 接收方会抛 `FileUriExposedException`）
3. `am start -a android.intent.action.SEND -t <mime> --eu android.intent.extra.STREAM <uri>`
4. 若手机解锁并能读到 `mCurrentFocus`，用 `-p <包名>` **直发前台 App**；
   读不到（锁屏）或该 App 无匹配 Activity 时，退回系统分享面板

包名简写：`wechat`/`wx` → `com.tencent.mm`，`qq` → `com.tencent.mobileqq`。

**边界**：这是「推送 + 分享」，不是真正的拖放——手机端仍需点一下确认（微信等
应用不允许外部静默发送）。真正的「拖进去直接发出去」在 Android 上无法实现。

### 启动器（ADR-18）

模板放在 `dotfiles/desktop/`，用 `__PROJECT_ROOT__` 占位，安装时替换成实际路径
（目录改名不会导致硬编码失效）。

**两个启动器**

| 文件 | 名称 | 作用 |
|---|---|---|
| `mobile-connect.desktop.template` | 手机投屏 | 连接 + 投屏 |
| `mobile-share.desktop.template` | 发送文件到手机 | 把文件拖到图标上 → push 并交给手机 App |

**`mobile-connect` 的 Action**

| Action | 命令 | 用途 |
|---|---|---|
| status | `--status` | 状态 + ARP/端口/adb 三段自诊断 |
| stop | `--stop` | 断开，并恢复手机息屏超时 |
| large | `MC_HEIGHT=900` | 大窗口（200% 缩放下 1800 物理像素） |
| x11 | `--x11` | XWayland 后端，**scrcpy 拖放可用** |
| port | `--port-prompt` | 端口变了，交互输入 |

**`mobile-share` 的关键是 `%F`**

其 `Exec` 为 `19-mobile-share.sh --share %F`。`%F` 让文件管理器把选中的文件
作为参数传入，因此支持「拖文件到图标」和「右键 → 用其他应用打开」；
手机端不需要装任何 App。

| 项 | 值 | 理由 |
|---|---|---|
| `Terminal=true` | 保留终端 | 端口变化、分享结果都要看到输出，否则双击后静默失败 |
| `StartupWMClass=scrcpy` | 窗口类 | 实测 WM_CLASS，确保图标与窗口正确关联 |
| `Icon=phone` / `document-send` | 图标 | 本机主题存在 |

安装（用户级）：

```bash
P="$HOME/CodeBuddy/work/linux-tune_SuonaOS"
mkdir -p ~/.local/share/applications
for n in mobile-connect mobile-share; do
  sed "s|__PROJECT_ROOT__|$P|g" "$P/dotfiles/desktop/$n.desktop.template" \
    > ~/.local/share/applications/$n.desktop
  chmod +x ~/.local/share/applications/$n.desktop
done
update-desktop-database ~/.local/share/applications 2>/dev/null || true
desktop-file-validate ~/.local/share/applications/mobile-connect.desktop \
                      ~/.local/share/applications/mobile-share.desktop
```

`mc` 别名与 4 个 dotfiles 断链修复见 `spec/04-tasks.md` TASK-35 对应命令块。
**脚本与启动器必须一起演进**：加了新的脚本参数，启动器也要同步加对应 Action。

### 5.3 窗口大小（高分屏适配）

本机 `xrandr` 报物理 `3072x1920`，但 GNOME 是 **200% 缩放**，
 Mutter `GetResources` 返回的逻辑桌面只有 `1536x960`，
所以 `--window-height` 必须用**逻辑像素**。

**曾经的坑**：脚本初版用了 `--max-size 1080`。该参数限制的是视频「宽和高都不超过」，
对 1080x2400 的竖屏手机等于把高度压到 1080、宽度按比例只剩 486，
窗口又默认跟随视频尺寸，于是显示成窄窄一条。

现在脚本：
- 读取 `wm size` 的 Override/Physical 得到视频比例（本机 1080x2400）；
- 默认窗口高度 **auto**：读 `xrandr` 物理高 ÷ `Xft.dpi` 缩放 − 40（本机 1920/2 − 40 = **920**）；
- 按比例算宽度 `920 × 1080 / 2400 = 414`；
- 想固定就写死：配置里 `WINDOW_HEIGHT=840`，或临时 `MC_HEIGHT=900`（`auto` 为默认）；
- `--window-width/--window-height` 显式指定窗口，**不再跟随视频尺寸**；
- `--max-size=1920` 仅限制编码分辨率（864x1920）控制无线带宽，不影响窗口大小。

投屏期间还会做两件「防熄屏」的事，退出后自动撤销：

| 对象 | 动作 | 说明 |
|---|---|---|
| 手机 | `screen_off_timeout` 临时设 `2147483647` | 退出时恢复原值（本机原值仅 **15 秒**，所以不设会秒熄） |
| 主机 | `systemd-inhibit --what=idle:sleep` | GNOME 默认 `idle-delay=300s`，不动键鼠 5 分钟就会黑屏锁屏，看起来像「投屏自己熄了」 |

想直接全屏（两侧留黑边、手机画面拉满高度）：

```bash
MC_FULLSCREEN=1 ./scripts/mobile-connect.sh
```

调整默认大小（三种方式，优先级从高到低）：

```bash
MC_HEIGHT=900 mc                      # 临时：本次用 900
# 或改配置永久生效
sed -i 's/^WINDOW_HEIGHT=.*/WINDOW_HEIGHT=900/' ~/.config/linux-tune/mobile.conf
# 或全屏（竖屏会有大黑边，一般不建议）
scrcpy -s 192.168.31.196:39959 --fullscreen
```

`MC_HEIGHT` 建议范围 `700~900`；超过 900 在 960 的逻辑屏幕上会被顶栏/Dock 挤掉。
改完脚本会自动把新值写回 `mobile.conf`。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `adb devices` 显示 `no permissions` | udev 规则缺失 | 见第 7 节 |
| scrcpy 报 `adb push` 失败 | HyperOS「USB 调试（安全设置）」限制 | 确认只开了普通 USB 调试；换 USB 口/线 |
| 投屏黑屏 | 手机锁屏 / 应用防截屏 | 解锁；银行类 App 本身禁止投屏 |
| 中文输入乱码 | `adb shell input text` 不支持中文 | 用 scrcpy 的 `Ctrl+V` 剪贴板注入 |
| 无线连接断开 | 手机休眠或 Wi-Fi 省电 | 开发者选项打开「充电时屏幕不锁定」，或保持亮屏 |
| 重跑 `03-perf-tune.sh` | — | 已加 avahi 白名单（ADR-14）；本方案不依赖 avahi |

## 7. udev 规则（仅当 `no permissions` 时）

```bash
# 位置：~　sudo：是　幂等：是
sudo tee /etc/udev/rules.d/51-android.rules >/dev/null <<'EOF'
# Xiaomi / Redmi
SUBSYSTEM=="usb", ATTR{idVendor}=="18d1", MODE="0666", GROUP="plugdev"
SUBSYSTEM=="usb", ATTR{idVendor}=="2717", MODE="0666", GROUP="plugdev"
EOF
sudo udevadm control --reload-rules
sudo udevadm trigger
sudo usermod -aG plugdev "$USER"
# 重新插拔 USB 线
```

`18d1` 是 Google（通用 ADB 接口），`2717` 是小米。用 `lsusb` 核对实际 idVendor。
