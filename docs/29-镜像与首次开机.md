# 29 · 镜像与首次开机

> 目录：`autoinstall/`　脚本：`scripts/29-suona-firstboot.sh`、`scripts/30-llm-verify.sh`
> 需求：`REQ-40`　关联：`SREQ-05`、`SREQ-06`、`S-31`、`S-44`、`SDEC-02`

## 1. 两手抓：检测先行，装机后置

产品级 spec 里有两件必须做的事，但都卡在外部条件上：

| 事 | 卡在哪 | 本项目现在能做的 |
|---|---|---|
| 11 款国产软件「开箱即用」 | SDEC-02 未裁决（预装 vs 可达） | 交付**检测工具**，把「缺哪款、从哪装」说清楚 |
| 本地 14B 大模型一键启动 | UM870 未到货、本机核显不在 ROCm 支持列表 | 交付**验证脚本**，诚实输出 NA/TOOL_MISSING |

所以本轮的产出不是「装好的镜像」，而是**装好之后能立刻验收的工具**。
这符合 8 步清单的口径：工具没交付就只能标 `TOOL_MISSING`，不能假装通过。

## 2. 首次开机自检（29）

```bash
./scripts/29-suona-firstboot.sh --list      # 11 款清单与来源
./scripts/29-suona-firstboot.sh --report    # 逐款可达性
./scripts/29-suona-firstboot.sh --report --json
./scripts/29-suona-firstboot.sh --install   # 只打印安装指引，不执行
```

判定口径：

| 已装数量 | 状态 | 含义 |
|---|---|---|
| 11 | `PASS` | 可写入交付记录 |
| 1–10 | `FAIL` | 缺的必须补齐再交付 |
| 0 | `NA` | 原型机未装这批软件，工具已交付但结论待目标机 |

**为什么默认不安装**：SDEC-02 没裁决前，自动下载第三方 `.deb` 有合规风险；
脚本里连 URL 都不写，只写「来源类型」。这是有意的克制，不是没做完。

## 3. 大模型验证（30）

```bash
./scripts/30-llm-verify.sh                 # 环境与模型
./scripts/30-llm-verify.sh --bench         # 实测 tok/s（需模型已下载）
./scripts/30-llm-verify.sh --model qwen3:14b --threshold 30 --bench
```

四状态：

| 状态 | 触发条件 |
|---|---|
| `PASS` | ROCm 识别 GPU + ollama 可用 + tok/s ≥ 阈值 |
| `FAIL` | 环境齐但指标不达标 / 模型缺失 |
| `NA` | 本机架构性不适用（740M 不在 ROCm 官方支持列表） |
| `TOOL_MISSING` | ollama 与 rocminfo 都没有 |

本机（T14 Gen 5 / 740M）预期落 `TOOL_MISSING` 或 `NA`：
- 没有安装 ollama → `TOOL_MISSING`
- 装了 ollama 但核显不受支持 → `NA`，并写明原因

**不允许**把「CPU 跑起来 8 tok/s」记成通过——第 7 步判据是 GPU 加速下的 14B tok/s，
口径见 `spec/suonaos/08-step-verification.md`。

## 4. autoinstall 骨架

`autoinstall/user-data.yaml` 目前只写「应该装什么、不该装什么」：

| 段 | 取值 | 理由 |
|---|---|---|
| `locale` / `timezone` | `zh_CN.UTF-8` / `Asia/Shanghai` | 目标用户在国内 |
| `storage` | `direct`（ext4） | Phase 1 不上 Btrfs；SREQ-09 留到 Phase 2 |
| `packages` | 全部来自官方源 | 第三方 deb 等 SDEC-02 |
| `late-commands` | 只拷检测脚本 | 不静默装包、不改引导 |
| 模型 | 不预下载 | 合规 + 体积 |

**未实测声明**：本文件没有在真机或虚拟机上跑过完整安装。
按 §2 的口径，它现在的状态是 `TOOL_MISSING`，不得写成「镜像已就绪」。

## 5. 与 8 步清单的接线

| 步 | 原来 | 现在 |
|---|---|---|
| 6 国产软件 | 固定 `TOOL_MISSING` | 调用 `29 --report --json`，按 0/部分/全部 给 NA/FAIL/PASS |
| 7 本地 LLM | 固定 `TOOL_MISSING` | 调用 `30` 的 `RESULT:` 行 |

注意：`step-verify.sh` 仍然坚持「工具在 ≠ 通过」，NA 与 TOOL_MISSING 单列，
不允许用「8 减失败数」冒充通过率。
