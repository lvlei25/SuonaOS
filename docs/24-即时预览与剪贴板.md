# 24 · 即时预览与剪贴板

> 脚本：`scripts/25-quicklook-clipboard.sh`
> 需求：`REQ-37`　决策：`ADR-35`（扩展例外为零的替代实现）

## 1. 为什么补这两块

`99-verify` 的既有 62 项里，桌面**配置**是全的，但有两个高频动作缺失：

| 缺失 | 用户实际行为 | 代价 |
|---|---|---|
| 文件即时预览 | 为了看一眼图片/PDF/文本，打开整个应用 | 每次多几秒，一天几十次 |
| 剪贴板历史 | 复制第二段就把第一段冲掉，只能回去再复制 | 上下文切换成本高 |

这两件事都属于「不需要新范式，只是缺一个动作」，适合直接补。

## 2. 即时预览：sushi

```bash
./scripts/25-quicklook-clipboard.sh --install   # 安装 sushi
```

- 行为：Nautilus 里选中文件按 **空格** 预览，再按空格关闭。
- 支持：图片、PDF、文本、音视频、字体（取决于已装 GStreamer 插件）。
- 不支持：Office 文档（`libreoffice` 未提供 sushi 渲染器），需要时仍要打开应用。
- 卸载：`sudo apt remove sushi`（脚本 `--restore` 不会自动卸载系统包，避免误伤）。

## 3. 剪贴板历史：不装扩展的实现

### 3.1 方案对比

| 方案 | 依赖 | 取舍 |
|---|---|---|
| GNOME 剪贴板扩展（Clipboard Indicator 等） | Shell 扩展 | 违反 ADR-24「少用扩展」，且扩展跟 Shell 版本强绑定 |
| `cliphist` + `rofi` | 需装两个包 + 一个面板程序 | 本机无 rofi；多一层 UI 不一致 |
| **`wl-paste` 轮询 + `fzf`** | 已装 `wl-clipboard`、`fzf` | **零新扩展、零新 UI 范式**，复用终端选择器；代价是每秒一次短进程 |

选第三种。代价是：选择界面是终端里的 fzf，不是漂浮面板——这是明确的取舍，
不是"以后再补"。

### 3.2 组成

```
~/.local/bin/suona-clip                          选择器与入库命令（含 --daemon）
~/.config/systemd/user/suona-clipboard.service   常驻 suona-clip --daemon
~/.local/share/applications/suona-clip.desktop   Terminal=true，供 gtk-launch 调用
~/.local/state/suona/clipboard.tsv               历史（base64，上限 200）
~/.local/state/suona/ignore                      自己写回剪贴板的内容，避免重复入库
```

数据流：

```
复制 → (1s 轮询 wl-paste) → 哈希去重 → 追加 + 截断
Super+Shift+V → gtk-launch suona-clip → fzf 选择 → wl-copy 回剪贴板（并写 ignore）
```

### 3.2.1 踩坑：`wl-paste --watch` 在 GNOME 上不可用

第一版用的是官方推荐的 `wl-paste --watch`，实机直接失败：

```
wl-paste: Watch mode requires a compositor that supports the wlroots data-control protocol
```

data-control 是 **wlroots 系合成器**（Sway/Hyprland 等）的协议，Mutter 不实现。
所以本机改为 1 秒轮询，实测无焦点进程也能读取 selection，开销可接受：
每秒一次短进程、常驻约 2 MB 内存。

这条记录保留在文档里，是因为「别人教程里能跑」不等于「这台机器能跑」——
与 ISSUE-21（不靠端口号猜用途）是同一类教训。

### 3.2.2 踩坑二：每次 `wl-paste` 都会让 Mutter 打一条断言

改用轮询后出现新问题：`journal` 里每秒一条

```
gnome-shell: meta_window_set_stack_position_no_sync: assertion 'window->stack_position >= 0' failed
```

精确计数确认是 1:1 —— 空转 10 秒 0 条，调用 `wl-paste` 10 次 10 条。
也就是说**每次轮询都触发一次窗口重排**，既刷日志，也可能让前台窗口闪一下（用户报「App 频繁重启」）。

处置：读取改走 XWayland 的 `xclip`（Mutter 的 X11 桥接不经过那段栈代码）：

| 方式 | 10 次调用产生的告警 | 能否读到 Wayland 应用复制的内容 |
|---|---|---|
| `wl-paste` | 10 条 | 能 |
| `xclip -o -selection clipboard` | **0 条** | 能（实测跟随 `wl-copy` 变化） |

现行实现：有 `DISPLAY` 且装了 `xclip` 就用 xclip，否则回退 `wl-paste`（并接受日志噪声）。
复测：切换后 20 秒内 0 条告警，历史采集正常（ISSUE-39）。

### 3.3 命令

```bash
suona-clip              # 选择一条并复制
suona-clip --store      # 供服务调用，一般不手工执行
suona-clip --list       # 当前条数
suona-clip --clear      # 清空历史
```

## 4. 隐私边界（必须知道）

| 项 | 事实 |
|---|---|
| 存储位置 | `~/.local/state/suona/clipboard.tsv`，仅本机 |
| 编码 | base64，**不是加密**；能读你 home 目录的人就能读它 |
| 范围 | 只采集**文本**选择；图片/文件路径不采集（`--type text`） |
| 上限 | 200 条，超出丢弃最旧 |
| 同步 | 不同步、不上传、不写日志 |
| 密码管理器 | 复制密码也会进历史。若介意：`suona-clip --clear`，或不用时 `systemctl --user stop suona-clipboard` |

这条边界写在这里而不是藏在代码里：剪贴板历史天然是敏感面，不装作没有。

## 5. 常用排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 复制后历史不增长 | 服务没起 | `systemctl --user status suona-clipboard`；`wl-paste --list-types` 自测 |
| `Super+Shift+V` 没反应 | 键位未写入 | 重跑 `24-keys-gestures.sh --install`；`--status` 看是否绑定 |
| 按了弹出终端但立刻退出 | 无历史 | 先复制一段文字；`suona-clip --list` 应为非 0 |
| 终端里 fzf 不可用 | `fzf` 未装 | `sudo apt install fzf` |
| 选了却没复制 | 条目被后续截断挤出 | 重开一次选择器 |

## 6. 回滚

```bash
./scripts/25-quicklook-clipboard.sh --restore
```

- 停用并删除 `suona-clipboard.service`、`suona-clip`、`suona-clip.desktop`
- 历史目录整体移入 `backup/<RUN_ID>/`（不是直接删，便于取证/恢复）
- `sushi` 包保留，需要时手工 `apt remove`

## 7. 为什么不做「概览呼出」

GNOME 50 的概览本身就是启动器：按 `Super` 输入即可搜索应用与文件。
再叠一个第三方启动器（Ulauncher 等）会引入第二套 UI 与快捷键语义，
属于"为了像某个系统而加壳"，违反 ADR-36。因此启动器入口就是概览。
