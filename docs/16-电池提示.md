# 16 · 电池关键节点提示

> 脚本：`scripts/13-battery-alert.sh`　决策：`ADR-29`　需求：`REQ-27`
> 配套：`docs/15-声音主题.md`（`battery-*` 事件音）、`docs/03-性能优化.md`（充电阈值）

只在**关键节点**响一次：20% 低电、10% 电量告急、充到上限停止。
电量从 76% 掉到 75% 这类日常变化**不发声**，也不会额外刷新图标
（图标由 upower 每 30 秒轮询驱动，属系统行为，与提示音无关）。

## 1. 分工：两个系统事件 + 一个自建事件

| 节点 | 事件名 | 谁触发 | 是否需要常驻 |
|---|---|---|---|
| 20% 低电 | `battery-low` | `gsd-power` 按 upower `warning-level=low` 播放 | 否，系统自带 |
| 10% 告急 | `battery-caution` | `gsd-power` 按 `warning-level=critical` 播放 | 否，系统自带 |
| 充到上限 | `battery-full` | 本项目 `suona-battery-alert.timer` | 是，每 5 分钟一次 oneshot |
| 插拔电源 | `power-plug` / `power-unplug` | `gsd-power` | 否，系统自带 |

关键发现：`/usr/libexec/gsd-power` 里内置了 `battery-caution`、`battery-low`、
`power-plug`、`power-unplug` 四个 libcanberra 事件名。但 freedesktop 主题
**没有** `battery-*` 文件，所以低电量一直是**静音**的。

因此 20% / 10% 不需要写任何守护进程——**把两个文件补进主题就行**：

```bash
strace -f -e trace=openat canberra-gtk-play -i battery-low 2>&1 | grep battery
# openat(..., "/home/suonaos/.local/share/sounds/Suona/stereo/battery-low.oga", O_RDONLY) = 16
```

「充满」没有对应事件，才需要自建。

## 2. 三档音色

| 事件 | 音高序列 | 实际峰值 | 听感 |
|---|---|---|---|
| `battery-low` | 392 → 294 lowwood（下行小三度） | −9.0 dBFS | 温和提醒 |
| `battery-caution` | 294 → 247 → 196 lowwood（三连下行） | −8.5 dBFS | 明显加急 |
| `battery-full` | 784 → 988 → 1318 wood/porcelain（上行） | −10.0 dBFS | 完成感，不喧闹 |

三者都走 `SYS_DECAY_DB` 全局衰减，与应用内容保持约 9 dB 差距（见 `docs/15` §5）。
电池类基准值比普通提示高 1 dB（−2.5 / −2），因为属于「必须注意到」的节点。

## 3. upower 阈值

GNOME 50 的 `org.gnome.settings-daemon.plugins.power` **没有** `percentage-*` 键，
阈值全部来自 `/etc/UPower/UPower.conf`：

| 键 | 默认 | 本项目 | 含义 |
|---|---|---|---|
| `PercentageLow` | 20.0 | **20.0**（未改） | 进入 low，`battery-low` |
| `PercentageCritical` | 5.0 | **10.0**（改） | 进入 critical，`battery-caution` |
| `PercentageAction` | 2.0 | 2.0 | 触发 `CriticalPowerAction`（HybridSleep） |

只改 `Critical`：5% 对笔记本来说太晚，用户要求 10%。
修改前 `backup_file` 会把原文件复制到 `backup/<RUN_ID>/files/etc/UPower/UPower.conf`
并登记 `logs/changes.tsv`，随后 `systemctl restart upower`。

## 4. 充满提示的实现

`suona-battery-alert.timer` 每 5 分钟跑一次 `--check`（oneshot，毫秒级）：

```
status = Discharging 或 AC=0        → 复位为 idle，退出
status = Full，或 capacity ≥ charge_control_end_threshold → 首次进入则播放
```

去重靠 `~/.local/state/linux-tune/battery-alert.state`：

| 状态 | 含义 |
|---|---|
| （空） | 从未触发 |
| `full-notified` | 已提示过，插着电时不再重复 |
| `idle` | 拔电/放电后复位 |

注意判定用的是 `charge_control_end_threshold`（当前 80%）而不是 100%：
本机开了电池养护，充到 80% 就停，`status` 变成 `Not charging`，
若只看 Full 永远不会触发。

## 5. 用法

```bash
./scripts/13-battery-alert.sh --install   # 装 timer + 改 upower 阈值（幂等）
./scripts/13-battery-alert.sh --status    # 电量、阈值、timer、内部标记
./scripts/13-battery-alert.sh --test      # 试听三个事件
./scripts/13-battery-alert.sh --check     # 单次检查（timer 调用）
./scripts/13-battery-alert.sh --restore   # 停 timer + 从备份恢复 UPower.conf
```

## 6. 验证证据

**单测（伪造 sysfs，不碰真实电池）**：脚本支持 `BAT_DIR` / `AC_ONLINE_FILE` 覆盖。

```bash
mkdir -p /tmp/fakebat
printf 'Full' > /tmp/fakebat/status
printf '80'   > /tmp/fakebat/capacity
printf '80'   > /tmp/fakebat/charge_control_end_threshold
printf '1'    > /tmp/fakeac.online

BAT_DIR=/tmp/fakebat AC_ONLINE_FILE=/tmp/fakeac.online ./scripts/13-battery-alert.sh --check
# → 播放 battery-full，state=full-notified
BAT_DIR=/tmp/fakebat AC_ONLINE_FILE=/tmp/fakeac.online ./scripts/13-battery-alert.sh --check
# → 幂等，不再播放
printf 'Discharging' > /tmp/fakebat/status; printf '0' > /tmp/fakeac.online
BAT_DIR=/tmp/fakebat AC_ONLINE_FILE=/tmp/fakeac.online ./scripts/13-battery-alert.sh --check
# → state=idle，复位
```

实测结果：`full-notified → full-notified → idle`，日志
`[2026-11-08 10:16:55] battery-full 已提示（80%，上限 80%）`。

**回归**：`99-verify.sh` 新增「电池提示」段 3 项（事件音齐全、阈值 20/10、timer 已启用），
总项数 54 → 57，零失败。

## 7. 已知限制

| 现象 | 原因 | 处理 |
|---|---|---|
| 充满提示最多延迟 5 分钟 | timer 间隔 300s（`AccuracySec=30`） | 想更快就改 unit 里的 `OnUnitActiveSec` |
| 电量下降过程中完全无声 | 设计如此：只有 low/critical/full 三个节点 | 若听到声音，按 `docs/99` 查 `power_supply` 事件与音频流 |
| 20% 提示后插回电源，再掉到 20% 不重复 | upower 的 `warning-level` 需要跨过阈值才会再次变化 | 属预期；`systemctl restart upower` 可重置 |
| 改 `PercentageCritical` 后需重启 upower | 配置只在启动时读取 | `--install` 已自动重启 |
| 重启 upower 后电池节点可能消失 | 本机 `thinkpad_acpi` 在阈值附近高频重注册，与 upower 重启竞争（ISSUE-29） | 脚本内置自愈：检测不到 `BAT*` 就重载 `thinkpad_acpi`；手动恢复见 `docs/99` |

## 7.1 挂起恢复自愈（ISSUE-31）

upowerd 缓存的 sysfs 句柄在 resume 后会失效，典型表现是**快捷键调不了键盘背光**
（日志刷 `error writing brightness 2`），顺带也可能影响电池图标刷新。

`scripts/17-sleep-hook.sh` 在 `/etc/systemd/system-sleep/50-suona-upower`
装了一个 hook，逻辑是**按需重启**：

```
post 阶段 → 等 upower 就绪 → 读 KbdBacklight.GetBrightness
  ├─ 成功 → 记日志、退出（不重启，避免触发 ISSUE-29）
  └─ 失败 → restart upower → 若 BAT* 消失则重载 thinkpad_acpi → 复验
```

只在真的坏了才动 upower，唤醒开销通常为一次 D-Bus 调用（毫秒级）。

```bash
./scripts/17-sleep-hook.sh --status   # hook / 键盘背光 / BAT0 状态
./scripts/17-sleep-hook.sh --test     # 模拟 post（正常时直接跳过）
./scripts/17-sleep-hook.sh --restore  # 卸载
```

日志：`journalctl -t suona-upower -n 10`。

## 9. 再出现「图标闪变 / 莫名提示音」怎么抓现场

现象是**阵发**的（upower 重启后、挂起前准备时会集中出现），静默窗口内抓不到，
所以要用后台三路监控等它自己出现：

```bash
cd ~/CodeBuddy/work/linux-tune_SuonaOS && : > logs/sound-trace.log

# 1) 谁在响：音频流创建时立刻 dump 来源
setsid bash -c 'stdbuf -oL pactl subscribe | while read -r l; do case "$l" in *sink-input*)
  printf "=== %s %s\n" "$(date +%T)" "$l"
  LC_ALL=C pactl list sink-inputs | grep -E "application.name|media.role";; esac; done' \
  >> logs/sound-trace.log 2>&1 < /dev/null &

# 2) 电池是否真的被移除/加回（只记 remove/add，不记高频 change）
setsid bash -c 'stdbuf -oL udevadm monitor --subsystem-match=power_supply --property |
  while read -r l; do case "$l" in ACTION=remove*|ACTION=add*) printf "%s %s\n" "$(date +%T)" "$l";; esac; done' \
  >> logs/sound-trace-udev.log 2>&1 < /dev/null &

# 3) 内核是否重注册电池
setsid bash -c 'journalctl -f -o short-iso | grep --line-buffered "battery 1 registered"' \
  >> logs/sound-trace-bat.log 2>&1 < /dev/null &
```

判读：

| 日志 | 含义 |
|---|---|
| `sound-trace.log` 有 `media.role = "event"` + `application.name = libcanberra/gnome-shell` | 系统音效，看时间对应哪个事件 |
| `sound-trace.log` 只有 `application.name = ncm-player/chrome/...` | 是应用自己的声音，不是系统提示音 |
| `sound-trace-udev.log` 出现 `ACTION=remove` | 电池节点真的被移除 → 图标会闪，按 `docs/99 §2.10` 处理 |
| `sound-trace-bat.log` 有记录但 udev 无 remove | 只是重注册，节点没消失，图标不该闪 |

**注意**：`pactl` / `udevadm` 输出到管道时是全缓冲，必须带 `stdbuf -oL`，
否则日志会一直是空的（本次排查踩过）。

停止监控：

```bash
ps -eo pid=,args= | awk '/pactl subscribe|udevadm monitor --subsystem-match=power_supply|journalctl -f -o short-iso/ && !/awk/ {print $1}' | xargs -r kill
```
