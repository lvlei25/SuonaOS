# 07 · 输入法（fcitx5 接管 + systemd 用户服务自启）

> 脚本：`scripts/07-ime-fcitx5.sh`
> 自启方案：**`~/.config/systemd/user/fcitx5.service`**（ADR-04）。
> 早期版本的 `.desktop` autostart 方案已废弃，本文与脚本均已同步。

## 1. 两个独立的问题

| 问题 | 现象 | 根因 |
|---|---|---|
| A. 装了不用 | `XMODIFIERS=@im=ibus`，fcitx5 的配置全部不生效 | 环境变量指向 ibus |
| B. 不自动启动 | 每次登录都要手动敲 `fcitx5 -d` | **im-launch 在 Wayland 下不启动守护进程** |

问题 B 容易被忽略。看 `/usr/bin/im-launch` 的逻辑：

```sh
if [ "$IM_CONFIG_ENTRY" = "xsession-im-launch" ] && [ "$XDG_SESSION_TYPE" != 'wayland' ]; then
    # start daemon for xsession and X11
```

只有 **X11 会话**才会 exec 启动输入法守护进程。Wayland 下 `im-launch` 只负责导出环境变量，
**不拉起进程**。所以即使 `im-config -n fcitx5` 配置正确，登录后 fcitx5 依然不启动。

这就是为什么本机「明明装好了 fcitx5、也配了变量，却永远不在」。
ibus 之所以能自启，是因为 GNOME Shell 内置了 ibus 集成，跟 im-launch 无关。

**怎么拉起进程**：最初用 `~/.config/autostart/` 下的 `.desktop` 自启项，但多次失败
（GNOME 对 `NoDisplay=true` + `X-GNOME-Autostart-Phase` 的处理不稳定），
且与后来的服务化方案并存会**双重拉起 fcitx5**。最终改为 **systemd 用户服务**（ADR-04），
由 `graphical-session.target` 触发，自带 `Restart=on-failure`，可靠且可观测。

## 2. 四层配置（缺一不可）

| 层 | 位置 | 解决什么 |
|---|---|---|
| 1. 系统输入法选择 | `~/.xinputrc`（`im-config -n fcitx5`） | 告诉 im-config「本机用 fcitx5」 |
| 2. 会话环境变量 | `~/.config/environment.d/99-input-method.conf` | 让 GUI 应用知道用 fcitx 的 im module |
| 3. 登录自启 | `~/.config/systemd/user/fcitx5.service` | **Wayland 下拉起并托管守护进程** |
| 4. GTK 模块通告 | `gsettings org.gnome.settings-daemon.plugins.xsettings overrides` | GTK3 应用通过 XSettings 拿到 IM 模块名，比单靠环境变量更可靠 |

### 2.1 im-config

```bash
im-config -n fcitx5
cat ~/.xinputrc      # run_im fcitx5
```

`im-config -l` 列出可用输入法（本机：`ibus fcitx5 xim`）。

### 2.2 会话环境变量

`~/.config/environment.d/99-input-method.conf`：

```ini
GTK_IM_MODULE=fcitx
QT_IM_MODULE=fcitx
XMODIFIERS=@im=fcitx
SDL_IM_MODULE=fcitx
GLFW_IM_MODULE=ibus
```

`GLFW_IM_MODULE=ibus` 是刻意的例外：GLFW（游戏、部分图形工具）对 fcitx 支持差。

### 2.3 登录自启（systemd 用户服务）

`~/.config/systemd/user/fcitx5.service`：

```ini
[Unit]
Description=Fcitx 5 Input Method
Documentation=man:fcitx5(1)
PartOf=graphical-session.target
After=graphical-session.target

[Service]
Type=simple
ExecStart=/usr/bin/fcitx5
Restart=on-failure
RestartSec=3
Environment=GTK_IM_MODULE=fcitx
Environment=QT_IM_MODULE=fcitx
Environment=XMODIFIERS=@im=fcitx

[Install]
WantedBy=graphical-session.target
```

要点：

- `ExecStart` 用**前台** `/usr/bin/fcitx5`（`Type=simple`），不要加 `-d`，
  否则进程脱离 cgroup，systemd 无法跟踪和重启。
- `PartOf=graphical-session.target` 保证退出图形会话时一起停止，不残留后台进程。
- `Environment=` 让服务自身也带上 IM 变量，与第 2 层的会话变量互为兜底。

启用与管理：

```bash
systemctl --user daemon-reload
systemctl --user enable --now fcitx5.service
systemctl --user status fcitx5.service          # 看状态与最近日志
journalctl --user -u fcitx5.service -f         # 实时日志
```

**改候选框主题后必须重启服务**（`fcitx5-remote -r` 只重载配置，主题/字体可能不刷新）：

```bash
systemctl --user restart fcitx5.service
```

脚本 `07-ime-fcitx5.sh` 会主动删除残留的旧 `.desktop` 自启项，
避免与 systemd 服务双重拉起进程。若手工配置过，检查并清理 `~/.config/autostart/`。

### 2.4 XSettings

```bash
gsettings set org.gnome.settings-daemon.plugins.xsettings overrides \
  "{'Gtk/IMModule': <'fcitx'>}"
```

这条让 GTK3 应用从 XSettings 读取 IM 模块，覆盖「从 GNOME 启动、不继承终端环境变量」的场景。

## 3. 踩坑记录：`fcitx5 -d` 会吞掉 shell 输出

> 主路径已由 systemd 服务托管（不需要手工启动）。本节记录的是脚本里
> `08-ime-theme.sh` 第三级冷启动兜底，以及排查时手工拉进程的坑。

在脚本里这样写会**看不到后续任何输出**：

```bash
fcitx5 -d          # 守护进程继承了 stdout，管道被一直持有
pgrep fcitx5       # 这行及之后的输出全部丢失
```

正确写法（子 shell + 全重定向 + 后台）：

```bash
( fcitx5 -d >/dev/null 2>&1 </dev/null & )
```

同理 `fcitx5 -r`（replace）在没有实例时可能直接退出，用 `-d` 更稳。
但如果 systemd 服务已启用，手工拉起的进程**不在服务 cgroup 内**，
`systemctl --user restart` 管不到它；排查完记得清理并用服务重启：

```bash
systemctl --user restart fcitx5.service
```

## 4. 生效与验证

环境变量对已运行的应用无效，**必须注销重登**。

```bash
# 重登后
echo $GTK_IM_MODULE                        # fcitx
echo $XMODIFIERS                           # @im=fcitx
systemctl --user is-enabled fcitx5.service # enabled
systemctl --user is-active fcitx5.service  # active
pgrep -x fcitx5                            # 有 PID 说明进程在跑
fcitx5-remote -n                           # 当前输入法名，如 pinyin / keyboard-us
fcitx5-remote                              # 1=启用, 2=禁用
fcitx5-diagnose | head -40                 # 官方诊断
journalctl --user -u fcitx5.service -n 20  # 服务日志
```

快捷键：`Ctrl+Space` 切换中英，`Ctrl+Shift` 切换方案，
`fcitx5-configtool` 图形化调整。

## 5. GNOME Shell 自身输入框：限制与取舍

| 场景 | fcitx5 是否可用 |
|---|---|
| GTK3/GTK4 应用（终端、编辑器、浏览器） | ✅ 可用 |
| Qt 应用 | ✅ 可用（fcitx5-frontend-qt5/qt6） |
| **GNOME Shell 自身输入框**（活动搜索、重命名文件、登录框） | ⚠️ **取决于是否启用 Kimpanel**，见下表 |
| 个别 Electron 应用 | ⚠️ 需加 `--enable-wayland-ime` |

GNOME Shell 的内置文本输入走自己的 ibus 集成，普通应用的 IM 模块够不着它。
但这**并非架构上的绝对禁令**——Kimpanel 是一条旁路：GNOME 扩展通过
D-Bus 与 fcitx5 通信，在 Shell 里绘制预编辑与候选框。

| 配置 | Shell 输入框 | 普通应用候选框主题 |
|---|---|---|
| **当前（禁用 kimpanel）** | 走内置 ibus，不能用 fcitx5 | ✅ classicui 主题/字体/圆角全部生效 |
| 启用 Kimpanel | ✅ 可由 fcitx5 接管 | ❌ 黑底灰框，classicui 配置被绕过 |

本机按 ADR-05 选择**前者**：优先保证日常输入时的候选框美观，代价是活动搜索框
无法用拼音。二者在 GNOME Wayland 下互斥，是产品取舍而非缺陷；切换方式与完整
说明见 [`08-输入法美化.md`](08-输入法美化.md) 第 6.4 节。

> 历史勘误：本文早期版本把 Shell 输入框写成「外部输入法无法接管」的架构定论，
> 该绝对化表述已被 ADR-05、ISSUE-04 的实测推翻，2026-11-05 更正。

## 6. 排查表

| 现象 | 检查 | 处理 |
|---|---|---|
| 登录后没有 fcitx5 进程 | `systemctl --user status fcitx5.service` | `systemctl --user enable --now fcitx5.service` |
| 服务反复重启 | `journalctl --user -u fcitx5.service -n 50` | 看具体报错；确认 `~/.config/fcitx5/` 配置无损坏 |
| 旧自启与服务双重拉起 | `ls ~/.config/autostart/` | 删除残留的 `fcitx5.desktop`，重启服务 |
| 有进程但打不出中文 | `fcitx5-remote -n` | 为空说明无输入方案，检查 `~/.config/fcitx5/profile` |
| 只有部分应用能输入 | `echo $GTK_IM_MODULE` | 变量没生效，检查 environment.d 并重登 |
| 改主题后候选框没变 | `systemctl --user is-active fcitx5.service` | 用 `systemctl --user restart`，别只 `fcitx5-remote -r` |
| Shell 搜索框打不出中文 | `grep -A2 DisabledAddons ~/.config/fcitx5/config` | 当前禁用 kimpanel 的取舍结果，见第 5 节 / `docs/08` 6.4 |
| 按 Shift 无效 | `fcitx5-configtool` → 全局配置 | 默认是 `Ctrl+Space`，可改 |
| 候选框位置错乱 | 附加组件 → 经典界面 | 勾选「使用客户端光标位置」 |

## 7. 回滚

```bash
systemctl --user disable --now fcitx5.service
rm -f ~/.config/systemd/user/fcitx5.service
systemctl --user daemon-reload
rm -f ~/.config/environment.d/99-input-method.conf
im-config -n ibus
gsettings reset org.gnome.settings-daemon.plugins.xsettings overrides
# 注销重登
```

> 回滚后若仍看到 fcitx5 进程，说明有旧的自启项或手工进程残留：
> `ls ~/.config/autostart/` 与 `pkill -x fcitx5`。

## 9. 顶栏图标风格（ADR-31）

现象：顶栏显示彩色红色「拼」字，与周围白色单色 symbolic 图标（Wi-Fi / 音量 / 电源）不一致。

根因在 kimpanel 扩展的 `lib.js`：它故意请求 `name + '-symbolic-hack'`
以绕过 GTK 的 symbolic 单色化，最终命中 `fcitx-pinyin.png`（红色位图），
不会随明暗主题变色。

修复由 `scripts/16-ime-icon.sh` 完成（幂等）：

1. 在用户图标目录提供 `fcitx-pinyin-symbolic.svg`（复用 Adwaita 的
   `input-keyboard-symbolic`，与 GNOME 原生输入法指示器同款）；
2. 给 kimpanel 加 `createSymbolicIcon()`，顶栏主图标请求 `-symbolic` 变体，
   找不到时 GTK 自动回落原彩色图标，不会变空。

生效需**注销重登**（Wayland 下不能 `Alt+F2 → r`）。扩展升级会覆盖补丁，
重跑 `./scripts/16-ime-icon.sh --install` 即可。详见 `docs/17` §3。
