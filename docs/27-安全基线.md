# 27 · 安全基线

> 脚本：`scripts/27-security-baseline.sh`
> 需求：`REQ-39`　验收指标：`A-05`（开放端口）、`A-06`（CVE < 72h）

## 1. 做了什么

| 项 | 配置 | 对应指标 |
|---|---|---|
| 入站默认拒绝 | `ufw default deny incoming` | A-05 |
| 出站允许 | `ufw default allow outgoing` | — |
| mDNS 放行 | `ufw allow 5353/udp` | 保住 avahi 设备发现（ISSUE-16） |
| 安全更新 | `unattended-upgrades` + `20auto-upgrades` | A-06 |
| 端口审计 | `ss -tulpn` 落盘到 `logs/port-audit-<RUN_ID>.txt` | A-05 |

## 2. 为什么放行 5353/udp

`ufw` 默认拒绝入站后，**组播也会被挡**。本机 avahi 在阶段 2 曾被误禁，
导致局域网设备发现失效（ISSUE-16）。这次显式放行：

```bash
sudo ufw allow 5353/udp comment 'mdns/avahi'
```

如果你不需要手机/打印机/投屏发现，可以删掉这条：

```bash
sudo ufw delete allow 5353/udp
```

**不做的事**：不默认放行 22（ssh）、不放开 5037（adb server 只监听 127.0.0.1），
不为了「方便」把默认策略改回 allow。

## 3. 使用

```bash
./scripts/27-security-baseline.sh --status     # 只读，先看现状
./scripts/27-security-baseline.sh --audit      # 端口审计
./scripts/27-security-baseline.sh --install    # 落地（会启用 ufw）
./scripts/27-security-baseline.sh --disable    # 回退
```

`--install` 是幂等的：重复执行不会重复添加规则（`ufw allow` 同样规则只留一条）。

## 4. 端口审计怎么读

```
协议     本地地址                 进程                   暴露面
tcp      127.0.0.1:631            cupsd                  仅本机
udp      0.0.0.0:5353             avahi-daemon           全接口
tcp      0.0.0.0:22               sshd                   全接口   ← 需要关注
```

判定规则：

| 暴露面 | 含义 | 处置 |
|---|---|---|
| 仅本机 | 回环，只影响本机进程 | 可接受 |
| 全接口 + 有 ufw 规则放行 | 主动开放 | 必须能说出理由 |
| 全接口 + 无放行 | 被 ufw 挡住 | 仍需确认服务是否必要 |

目标：**没有任何「全接口 + 无理由」的监听**。

## 5. 自动更新的边界

- 只开安全源（Ubuntu 的 `-security` 已在 `50unattended-upgrades` 默认列表内）。
- 不做「全量自动升级」：桌面大版本自动升级会绕过你快照打点的节奏。
- 更新时段由 `apt-daily-upgrade.timer` 决定，默认在开机后随机延迟；批量交付时可统一。

验证：

```bash
systemctl is-enabled unattended-upgrades.service
systemctl list-timers 'apt-daily*' --no-pager
grep -c security /etc/apt/apt.conf.d/50unattended-upgrades
```

## 6. 误封排查（按症状）

| 症状 | 原因 | 处理 |
|---|---|---|
| 手机投屏连不上 | adb 走**出站**连接，通常不受影响；若手机主动连本机则需放行 | 先 `ss -tulpn` 看端口，再决定放行 |
| 局域网打印机找不到 | mDNS 被挡 | 确认 5353/udp 放行；`avahi-browse -a` |
| ssh 连不上本机 | 未放行 22 | `sudo ufw allow 22/tcp`（明确决定后再开） |
| Docker 容器访问异常 | ufw 与 Docker 的 iptables 链冲突 | 本项目不装 Docker；如装需单独配 `DOCKER_OPTS` |
| 网络共享（Samba）不可用 | 未放行 137-139/445 | 按需放行，并确认只在内网 |

排查顺序：`ufw status verbose` → `ss -tulpn` → 应用日志。**不要先关防火墙试**。

## 7. 回退

```bash
./scripts/27-security-baseline.sh --disable
sudo systemctl disable --now unattended-upgrades
```

回退后 `step-verify.sh` 第 8 步会记录「ufw 未启用」——这是**如实记录**，不是失败，
由产品决定是否在目标机型默认开启（8 步清单第 8 步的口径）。
