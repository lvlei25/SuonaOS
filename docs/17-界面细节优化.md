# 17 · 界面细节：日落深色 / 圆角 / 输入法图标

> 脚本：`scripts/14-auto-dark.sh`、`scripts/15-rounding.sh`
> 决策：`ADR-30`、`ADR-31`　需求：`REQ-28` / `REQ-29` / `REQ-30`

三项互相关联：都要改「用户级界面层」，都不碰系统目录，都能一条命令回滚。

## 1. 深色模式随日落自动切换

### 1.1 为什么不用现成方案

| 方案 | 问题 |
|---|---|
| GNOME 夜灯（Night Light） | 只调色温，不改 `color-scheme`，应用不会变深色 |
| 第三方扩展（Night Theme Switcher 等） | 引入 Shell 扩展依赖，与 ADR-24「少用扩展」相悖 |
| geoclue 定位 | 需要额外服务与授权，国内定位常失败 |
| **本地算日出日落 + user timer** | 零依赖、可离线、可配置坐标 |

### 1.2 实现

日出日落用 **NOAA 简化算法**在本地算（Python 标准库，无网络）：

```bash
./scripts/14-auto-dark.sh --status
# 城市      : 上海（31.2304, 121.4737）
# 日出/日落 : 06:15 / 17:01
# 应有模式  : dark
```

每 10 分钟由 `suona-auto-dark.timer` 触发一次 `--check`：

```
日出 ≤ 当前 < 日落  → light : color-scheme=default  + Yaru-prussiangreen
否则                → dark  : color-scheme=prefer-dark + Yaru-prussiangreen-dark
```

**只写两个键**：`color-scheme`（libadwaita 应用）与 `gtk-theme`（GTK3 应用）。
两者都设是为了覆盖两类应用，缺一个就会出现「一半应用没变色」。

状态去重：`~/.local/state/linux-tune/auto-dark.state` 记住上次模式，
没跨过日出/日落就不重复写 gsettings，避免整点抖动。

### 1.3 换城市

```bash
./scripts/14-auto-dark.sh --lat 39.9042 --lon 116.4074 --city 北京 --install
```

坐标与城市名写进 `~/.config/linux-tune/auto-dark.conf`，重跑不丢。

### 1.4 一个必须修的前提

原来 `~/.config/gtk-4.0/gtk.css` 是**软链到一份 9424 行的 `gtk-Dark.css`**。
这意味着所有 GTK4/libadwaita 应用**永远暗色**，`color-scheme` 写什么都不生效，
日落切换对它们等于没做。

已按 ADR-30 移除软链，改成只含圆角覆盖的普通文件（见 §2），
原文件备份在 `backup/20261108-192059/`。

## 2. 圆角优化

### 2.1 范围

| 层级 | 是否调整 | 说明 |
|---|---|---|
| GTK4 / libadwaita 应用（设置、文件、文本编辑器…） | ✅ | 窗口外壳 14px、弹层 14px |
| GTK3 应用 | ✅ | 只调 `decoration` 外框，不动控件 |
| GNOME Shell 弹窗 / 通知 / 快捷设置 / OSD | ✅ | 独立 shell 主题 `Suona-Round`，只覆盖圆角并 `@import` Yaru 全套 |
| Dock | ✅ | `#dashtodockContainer .dash-background` 圆角 20px |

### 2.2 做法

```bash
./scripts/15-rounding.sh --install              # 14px
./scripts/15-rounding.sh --install --radius 18  # 更大
./scripts/15-rounding.sh --status
./scripts/15-rounding.sh --restore
```

GTK4 覆盖层内容（节选）：

```css
window.csd { border-radius: 14px; }
window.csd > .titlebar { border-radius: 14px 14px 0 0; }
window.csd > .titlebar:only-child { border-radius: 14px; }
popover > contents { border-radius: 14px; }
```

**刻意只覆盖外壳**：改控件内部的 `border-radius` 会让按钮、输入框、卡片
的圆角互相不一致，还要逐个对齐 Yaru 的尺寸变量，收益小、维护成本高。

### 2.3 Shell 层（菜单 / 通知 / Dock）

GNOME Shell 的圆角只能由 shell theme 控制，GTK CSS 管不到。做法是建一个
**叠加式**用户主题：只写圆角，其余全部 `@import` 系统 Yaru。

```css
@import url("file:///usr/share/themes/Yaru/gnome-shell/gnome-shell.css");

.popup-menu-content { border-radius: 14px; }
.quick-settings { border-radius: 18px; }
.message-list .message { border-radius: 14px; }
.osd-window { border-radius: 14px; }
#dashtodockContainer .dash-background { border-radius: 20px; }
```

通过 `user-theme` 扩展激活：

```bash
gsettings set org.gnome.shell.extensions.user-theme name Suona-Round   # 即时生效
gsettings set org.gnome.shell.extensions.user-theme name ''            # 立即回退
```

与 ADR-07「回系统默认外观」**不冲突**：只加圆角，配色/图标/布局全部继承 Yaru，
主题名带 `Suona-` 前缀，体检脚本据此区分「圆角覆盖」与「恢复浮夸主题」（ADR-32）。

### 2.4 生效范围

- 新开的窗口立即生效
- 已打开的应用需要重开（GTK 在启动时加载 `gtk.css`）
- 部分应用（Electron / 自带 CSS 的应用）不读 GTK CSS，圆角不变

## 3. 输入法顶栏图标与系统不一致

### 3.1 现象与根因

顶栏显示一个**彩色红色「拼」字**，而周围 Wi-Fi、音量、电源都是白色单色 symbolic。

根因在 kimpanel 扩展的 `lib.js`：

```js
// 原代码：故意请求一个不存在的名字，绕过 GTK 的 symbolic 单色化
return Gio.ThemedIcon.new_with_default_fallbacks(name + '-symbolic-hack');
```

fcitx5 给的图标名是 `fcitx-pinyin`，最终命中 `/usr/share/icons/hicolor/48x48/apps/fcitx-pinyin.png`
——一张**红色方块位图**，不随明暗主题变色。

### 3.2 修复（两处，都不动系统目录）

1. **提供 symbolic 版本**（用户级，优先于系统）：
   `~/.local/share/icons/hicolor/scalable/apps/fcitx-pinyin-symbolic.svg`
   —— 直接复用 Adwaita 的 `input-keyboard-symbolic`，与 GNOME 原生输入法指示器同款。

2. **补丁 kimpanel**：新增 `createSymbolicIcon()`，顶栏主图标请求 `name + '-symbolic'`：

   ```js
   export function createSymbolicIcon(name) {
       if (!name) return null;
       if (name[0] == '/') return Gio.FileIcon.new(Gio.File.new_for_path(name));
       return Gio.ThemedIcon.new_with_default_fallbacks(name + '-symbolic');
   }
   ```

   `indicator.js` 的 `_setIcon()` 改用它（菜单项仍用原 `createIcon`，保持彩色菜图标）。
   找不到 symbolic 版本时 GTK 会自动回落到原彩色图标，不会变空白。

### 3.3 生效与注意事项

- **需要注销重登**（Shell 启动时加载扩展代码与图标缓存）
- 扩展升级会覆盖补丁，重跑 `scripts/16-ime-icon.sh --install` 即可
- 其他输入法（英文 `fcitx-keyboard-*`）没有自定义 symbolic，会回落原图标，
  如需要按同样方式补一个同名 SVG
