# 电池 ACPI 枚举抖动（BAT0 间歇消失）

> 机型：ThinkPad T14 Gen 5 (AMD)，21MCCTO1WW，BIOS 1.23
> 结果：**已自愈**，记录供复发时对照。

## 1. 现象

| 表现 | 说明 |
|---|---|
| 顶栏无电池图标 | 系统认为没有电池 |
| 偶尔闪现电量 | 几十秒出现一次，维持十几秒又消失 |
| 间歇提示音 | 与闪烁同步 |
| **未接电源不关机** | 电池实际在供电，硬件没坏 |

## 2. 时间线

```
11-10 23:17  本次启动（内核 7.0.0-42）
11-13 20:14  upowerd: value "-nan" ... property 'percentage'
11-13 21:02  upowerd: Fail on setting charging threshold
11-14 22:48  upowerd: no valid voltage value found for ... BAT0
11-15 09:29  重启（切内核 7.0.0-43）后仍无 BAT0
11-15 09:31  实测抖动：4~16 秒出现，40~45 秒消失
11-15 09:48  短暂稳定：BAT0 出现约 30 分钟，52% 放电中
11-15 09:53  复发：`_STA` 31↔15 反复切换，BAT0 每几十秒闪一次
```

## 3. 关键证据

故障期间的矛盾状态：

| 层面 | 状态 | 结论 |
|---|---|---|
| `/sys/class/power_supply/` | 无 `BAT0` | 系统看不到 |
| ACPI `_STA` | **31 ↔ 15 反复切换** | **bit4（电池存在）由 EC 翻转** |
| `/sys/bus/acpi/drivers/` | 无 `acpi_battery` | 驱动没注册 |
| `PNP0C0A:00/driver` | 不存在 | 未绑定 |
| dmesg | **零条** battery 日志 | 静默失败 |
| `/sys/module/battery/` | 只有 `parameters` `uevent` | 模块 init 失败特征（正常应有 sections/holders/refcnt） |

**`_STA` 位义（ACPI 规范，电池设备专有 bit4）**

```
31 = 0b11111  存在|启用|显示|正常|电池存在
15 = 0b01111  存在|启用|显示|正常|电池不存在   ← bit4 被 EC 清零
```

实测切换（09:55~09:56）：

```
09:55:12  BAT0=有  _STA=31
09:55:18  BAT0=无  _STA=15      ← EC 说「没有电池」
09:55:21  BAT0=有  _STA=31
09:56:21  BAT0=无  _STA=15
09:56:23  BAT0=有  _STA=31
```

**设备的存在性跟着 `_STA` 走**，说明内核只是如实响应 EC 的声明——不是驱动 bug，也不是内核 bug。

## 4. 实测抖动

```
09:31:52  off
09:32:02  on:58%:Discharging     ← 出现
09:32:06  off                    ← 4 秒后消失
09:32:48  on:58%:Discharging     ← 42 秒后重现
09:33:04  on:57%:Discharging     ← 电量正常下降
09:33:08  off
```

紧接的 120 秒采样：一次都没出现。**间歇性**。

## 5. 根因

```
电池 BMS → EC → ACPI 命名空间 → acpi_battery 驱动 → upower → GNOME
```

卡在 **EC → ACPI**：EC 间歇把 `_STA` 置 0，内核注销 `power_supply` 设备，几十秒后又恢复。

后果链：

- 设备消失 → upower 发 `DeviceRemoved` → `gsd-power` 认为电池被拔 → 播 `power-unplug`
- 设备出现 → 发 `DeviceAdded` → 播 `power-plug`

**这就是"间隔提示音"的来源，不是 `13-battery-alert.sh`**（该脚本日志在 11-13 之后零触发）。

## 6. 短暂稳定后复发（不是自愈）

11-15 09:48 重启后稳定了约 30 分钟（电量 53%→50% 正常下降，充电阈值可读写），
但 09:53 起抖动重现：

```
09:53:04  off
09:53:11  on:50%:Discharging
09:53:40  off
09:53:41  on:50%:Discharging
```

**所以「重启即修复」不成立**，只是 EC 短暂恢复正常。

稳定期观察到的正常指标（可作为 EC 通信正常的对照）：

```bash
$ cat /sys/class/power_supply/BAT0/charge_control_end_threshold
80                      # 故障时写入失败，现在可正常读写
```

| 指标 | 故障时 | 恢复后 |
|---|---|---|
| upower `percentage` | `-nan` | 52% |
| 电压 | `no valid voltage, assuming 10V` | 正常 |
| 充电阈值写入 | `Fail on setting charging threshold` | 成功（75/80） |
| 设备稳定性 | 40 秒闪一次 | 90 秒仅 2 次正常变化 |

电池健康：`52.92 Wh / 52.57 Wh 设计`，`100%`，`3 次循环`——接近全新。

## 7. 复发时的处理顺序

1. **重启**（先试，EC 状态重置）
2. **EC 静电复位**：完全关机 → 拔电源 → 长按电源键 30 秒 → 接电开机
3. **BIOS 复位电池**：F1 → `Config` → `Power` → `Disable Built-in Battery` → 自动关机 → 接电开机
4. **报修**：BIOS 里也看不到电池 → 电池/排线硬件故障

**BIOS 已是最新**（1.23，官网 2026-09-08 发布），没有固件更新可装。

## 8. 诊断命令

```bash
# 设备在不在
ls /sys/class/power_supply/
upower -e | grep -i bat

# 驱动绑定情况
ls -l /sys/devices/.../PNP0C0A:00/driver
cat  /sys/devices/.../PNP0C0A:00/status      # 15=存在 0=不存在
ls   /sys/module/battery/                    # 只有 2 项=init 失败

# upower 报错
journalctl -u upower --since '1 hour ago' | grep -iE 'nan|no valid voltage|threshold'

# 抖动监测（每 2 秒，3 分钟）
for i in $(seq 90); do
  [ -d /sys/class/power_supply/BAT0 ] \
    && echo "$(date +%T) on:$(cat /sys/class/power_supply/BAT0/capacity)%" \
    || echo "$(date +%T) off"
  sleep 2
done | uniq -f1
```

## 9. 预防

故障出现在**连续运行 5 天**之后。建议每周重启一次，避免 EC 状态长时间累积。

## 10. 遗留

- 提示音来自 `gsd-power`，GNOME 没有单独开关，只能等设备稳定
- 若再次抖动，电池不可见期间**拔电源会直接断电**（无低电预警），需保持接电
