# 28 · 外设与电源

> 脚本：`scripts/28-peripherals-power.sh`、`scripts/battery-check.sh`
> 需求：`REQ-40`　关联：`ISSUE-33`、`ISSUE-31`

## 1. 外设矩阵

一条命令看清「这台机器现在接了什么」：

```bash
./scripts/28-peripherals-power.sh --status
./scripts/28-peripherals-power.sh --status --audit   # 同时落盘到 logs/
```

| 类别 | 检查内容 | 数据来源 |
|---|---|---|
| 显示输出 | 已连接接口 + 首选分辨率 | `/sys/class/drm/card*-*/status` + `modes` |
| USB-C / 扩展坞 | `data_role` / `power_role` / 是否有 partner | `/sys/class/typec/port*` |
| 打印机 | 队列名与状态 | `lpstat -p` |
| 扫描仪 | 设备列表 | `scanimage -L` |
| 蓝牙 | 已连接设备 | `bluetoothctl devices Connected` |
| 电池 | 电量 / 状态 / 充电阈值 | `/sys/class/power_supply/BAT*` |
| 触摸板 | 点按 / 自然滚动 | `gsettings` |

判定口径：

- **已连接但分辨率为空** → EDID 读取失败，先换线/换口，不要急着改驱动。
- **typec 有 partner 但无数据角色** → 线是充电线，不是全功能线（常见坑）。
- 外设矩阵**不做自动化断言**：接什么由用户决定，脚本只负责如实呈现。

## 2. 电池枚举抖动（ISSUE-33）

### 2.1 现象

顶栏电量间歇消失，`/sys/class/power_supply/BAT0` 每 40 秒左右消失一次，
伴随 `percentage=-nan`、`no valid voltage`，过一会儿又自己回来。

### 2.2 已知事实（来自 ISSUE-33 的实测记录）

| 观测 | 结果 | 推论 |
|---|---|---|
| ACPI `_STA` | 在 `31` ↔ `15` 之间翻转（bit4 = 电池存在位） | EC 在改「电池存在」位 |
| 电量 | 3 分钟内恒为 47%，仍翻转 5 次 | **不是电量变化触发** |
| 自建 timer | 停掉后抖动频率不变 | **不是检查频率干扰** |
| 重启后 | 短暂稳定约 30 分钟后复发 | 软件复位只能延后，不能根治 |

结论：`_STA` 由 EC 固件提供，**软件层无法干预**。这不是配置问题，
所以本项目的处理方式是「测出来 + 按流程处置 + 交付前拦住」，而不是写脚本硬修。

### 2.3 量化抖动率

```bash
./scripts/28-peripherals-power.sh --battery 60
```

输出：缺失次数、缺失占比、状态翻转次数、近 10 分钟内核 `power_supply` 日志行数。

| 缺失占比 | 判定 | 处置 |
|---|---|---|
| 0% | 稳定 | 正常交付 |
| < 20% | 偶发抖动 | 记录，交付前复测 |
| ≥ 20% | 频繁抖动 | 按 §3 走硬件流程 |

## 3. 处置顺序（不可跳步）

```
1. EC 静电复位
   关机 → 拔电源 → 长按电源键 15~30 秒 → 接电开机
2. BIOS 复位电池
   开机按 F1 进 BIOS → Power → 执行电池复位/断开 → 保存重启
3. 报修
   前两步后仍抖动 = 电池或 EC 硬件问题，走保修
```

顺序理由：软件层的 `modprobe thinkpad_acpi` 只能让节点重新枚举（ISSUE-29 用过），
对 `_STA` 翻转无效；先做无成本的静电复位，再动 BIOS，最后才是报修。

## 4. 交付前电源门禁

```bash
./scripts/28-peripherals-power.sh --gate --minutes 5
```

- 5 分钟内每 2 秒采样一次 `BAT*` 是否存在；
- **任何一次消失都判失败**，退出码 1，不得交付；
- 通过后建议同时看 `battery-check.sh` 的健康度与循环次数。

为什么门槛是「一次都不能消失」：用户看到的不是「40 秒消失一次」，
而是「电量突然没了」，这属于交付级缺陷，不是可接受的偶发。

## 5. 与其它脚本的关系

| 脚本 | 角色 |
|---|---|
| `battery-check.sh` | 深度诊断：DMI、健康度、upower、内核日志 + 10 秒连续性采样 |
| `28-peripherals-power.sh` | 快速矩阵 + 抖动量化 + 交付门禁 |
| `preboot-check.sh` | 重启前的电池枚举连续性抽检（8 秒） |
| `17-sleep-hook.sh` | 挂起/恢复后 upower 句柄自愈（ISSUE-31） |

## 6. 已知局限

- `_STA` 本身读不到（需 ACPI 表反编译），脚本只能观测「节点在不在」，这是**可观测事实的上限**，不臆造读数。
- 门禁是时间窗口采样，理论上可能错过极短翻转；5 分钟 × 2 秒的窗口对「40 秒一次」的故障足够。
- 外接显示器/扩展坞的兼容性只能在具体硬件上试，脚本不做「应该能用」的判断。
