## 9. 优化后复测（2026-11-05 23:58）

> 采集命令：`./scripts/bench.sh`、`systemd-analyze`、`systemd-analyze blame`
> **数据有效性**：首次重启曾遇 EC/SMU 状态异常导致 CPU 锁在 528MHz（python 求和 8.2s、
> sha256 仅 36 MB/s），该次开机数据全部作废。以下为**完整断电复位后**的有效数据。

### 9.1 启动耗时对照

| 阶段 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| firmware | 9.171s | 9.182s | ≈ 0（固件固有） |
| loader | 3.818s | **7.191s** | **+3.373s** |
| kernel | 0.903s | 0.984s | +0.081s |
| initrd | 1.393s | 1.365s | −0.028s |
| **userspace** | **11.122s** | **6.903s** | **−4.219s（−38%）** |
| **总计** | **26.408s** | **25.626s** | **−0.782s（−3%）** |

**为什么总共只快了 0.8 秒**：userspace 省下的 4.2s 几乎被 loader 增加的 3.4s 抵消。
`GRUB_TIMEOUT` 按 ADR-03 保留 5s（Windows 双系统需选菜单），基线那次实测 3.818s
是倒计时被提前打断的结果。这是**主动取舍**，不是优化失败。

| 单元 | 优化前 | 优化后 |
|---|---|---|
| `NetworkManager-wait-online.service` | **6.633s** | 已禁用，不再出现 ✓ |
| USB 设备 `.device` | 4.271s | 3.168s |
| `dev-rfkill.device` | 2.748s | 2.272s |
| `plymouth-quit-wait.service` | — | 3.459s |

> `systemd-analyze blame` 里 `snapd.service 4h53min`、`apt-daily-upgrade 48.9s`
> 是**单元累计运行时长**，不是启动阻塞耗时，不参与上表对比。

### 9.6 增量优化后的性能复核（2026-11-08 20:08）

本轮新增：Suona 声音主题（34 个事件）、电池节点提示（2 个 user timer）、
日落自动深色（1 个 user timer）、GTK/Shell 圆角覆盖层。
复核目的：确认这些改动没有引入性能回退。

| 基准 | 11-05 优化后 | 11-08 复核（3 次采样） | 判定 |
|---|---|---|---|
| python 求和 1e7 | 0.13s | **0.11 / 0.11 / 0.11s** | 略快，无退化 |
| sha256 吞吐 | 1036 MB/s | **1062 MB/s** | 持平 |
| 磁盘写（direct 1GB） | 1868 MB/s | **2081 MB/s**（复测 2.5~2.8 GB/s） | 更好 |
| CPU 频率均值 | 2712 MHz | **3637 MHz** | 无锁频 |
| governor / platform | performance | performance / performance | 未变 |
| userspace 开机 | 6.903s | **7.074s（+0.171s）** | 见下 |

开机 +0.17s 不归因于本轮改动：`apt-daily-upgrade.service` 占 4.746s（后台更新，
未禁用属既有决策），`systemd-suspend.service 2.965s` 是**上次挂起**的累计时间、
不在启动关键路径。新增的两个 timer 都用 `OnBootSec` 延迟启动（45s / 90s），
根本不参与开机流程。

**新增常驻开销（实测）**：

| 项目 | 单次耗时 | 频率 | 折算单核占用 |
|---|---|---|---|
| 电池提示 `--check` | 62~68 ms | 每 300s | ≈ 0.02% |
| 日落切换 `--check` | 97~115 ms | 每 600s | ≈ 0.02% |
| Shell 圆角主题 | 一次性 CSS 解析 | 仅登录/切换主题时 | 0 |

累计 CPU（自本次启动）：电池 timer 86 ms、日落 timer 60 ms。
电池 timer 已从 60s 放宽到 300s 后，两者合计长期占用 **< 0.05% 单核**，在噪声范围内。

**结论：无性能回退。** 已在同日把电池 timer 的 `OnUnitActiveSec`
从 60s 放宽到 **300s**，两项 timer 合计占用降到 **< 0.05% 单核**，
代价是「充满提示」最多延迟 5 分钟。
