5.2 关键调优：Mutter 动态三重缓冲 + 动效系统

这是 SuonaOS 流畅度的核心壁垒——2025 年由 Daniel van Vugt（Canonical）合并入 GNOME 48，Ubuntu 26.04 默认启用。我们要做的是：

  1. 确认 UM870 平台下三重缓冲实际工作（Intel 核显案例是 4K 概览 30→60 FPS，需 AMD 780M 复测）
  2. 向上游提交 AMD 780M (gfx1103) 三重缓冲的回归 patch（System76 模式：先解决自家问题，再贡献社区）
  3. 动效曲线调成"macOS-like"：开窗 200ms / 关闭 150ms / 调度 250ms（elementary Pantheon 已验证这套参数）

5.3 atomic update / immutable 路线

Phase 1 用传统 apt + Btrfs 快照（保留用户习惯）；Phase 2 切换到 bootc/ostree（参考 SteamOS 经验）。

为什么 Phase 1 不上 ostree？

ostree 改造工作量 6–12 个月，会拖慢 MVP 节奏。Phase 1 用 btrfs-assistant + snapper 提供"开机时保留 5 个快照可回滚"的轻方案——openSUSE Aeon 验证了这条过渡路径。Phase 2 切到 ostree 是产品差异化壁垒的强化项，不是 Phase 1 阻塞项。

6.2 SuonaOS 的护城河：开箱即用，不让用户踩任何一个坑

上面 11 个软件每一个在原始 Ubuntu 26.04 上都有踩坑点，合计用户首次开机要花 2–6 小时配置——SuonaOS 的核心价值是"开箱即用，全部预装 + 全部修好"。具体动作：

  1. 构建 suona-firstboot 服务：首次启动自动检测每个软件的依赖、镜像源、Wayland 兼容、字体环境
  2. 对钉钉等"需 patchelf"的软件，包装成 .deb 后置脚本（postinst）自动运行 patchelf 修复，用户无感
  3. 自研 SuonaOS Software Center 聚合 apt/Flatpak/Snap/官方 .deb，明确标注来源与版本（避免出现"搜索微信出来 electronic-wechat"的悲剧）
  4. Flatpak 默认配置国内镜像（中科大/阿里），下载速度从 KB/s 提到 10+ MB/s
  5. 针对 Wayland 屏幕共享问题，默认提供 X11 会话选项，并在登录界面说明

⚠️ 6.3 国产软件合规与法律风险

微信/QQ/飞书/钉钉等非开源，预装可能涉及《计算机软件保护条例》与各家用户协议。SuonaOS 采取"提供官方源 + 用户自行安装"模式，不内置 .deb 包，而是在 Software Center 提供一键下载跳转官方页面——这是最安全的合规姿态。微信等通过 Flatpak 沙箱安装也是合规解。

7.1 技术路径

步骤命令/工具SuonaOS 做了什么

7.3 中文 LLM 优先策略

  • 预装"中文 AI 助手"桌面应用（基于 Open WebUI 定制），一键对话、知识库、文档总结

  • 针对中文 UI/字体/输入法做了端到端优化，不是英文系统套个中文界面
